TypeScript で「値にどんな型を持たせるか」「どんな値だけを許可するか」を少しずつ理解できた。

## 1. Tuple について学んだ

Tuple は、配列のように見えるが、中に入る値の数と型の順番を決められる型。

```ts
const person: {
  name: string;
  age: number;
  hobbies: string[];
  role: [number, string];
} = {
  name: "yota",
  age: 30,
  hobbies: ["Sports", "Cooking"],
  role: [2, "author"],
};
```

このコードでは、`role: [number, string];` としているため、role は必ず `[number, string]` の形になる。

通常の配列 `string[]` は「文字列が何個入ってもいい配列」だが、Tuple は「何番目にどの型が入るか」を決められる。

## 2. Enum について学んだ

Enum は、決まった値に名前をつけて管理する仕組み。

```ts
enum Role {
  ADMIN = "ADMIN",
  READ_ONLY = 100,
  AUTHOR = 200,
}
```

以前のように、

```ts
const ADMIN = 0;
const READ_ONLY = 1;
const AUTHOR = 2;
```

とバラバラに定数を作る代わりに、Enum を使うとまとめて管理できる。

```ts
const person = {
  name: "yota",
  age: 30,
  hobbies: ["Sports", "Cooking"],
  role: Role.ADMIN,
};

if (person.role === Role.ADMIN) {
  console.log("管理者ユーザー");
}
```

Role.ADMIN と書くことで、「管理者」という意味がコード上で分かりやすくなる。

0 や "ADMIN" を直接書くよりも、意味が明確で、タイポも防ぎやすい。

## 3. any について学んだ

any は、どんな型でも入れられる型。

```ts
let favoriteActivities: any[];
favoriteActivities = ["Sports", 5];
```

any[] は「何でも入れられる配列」という意味。そのため、文字列の "Sports" と数値の 5 が混ざっていてもエラーにならない。

ただし、any を使うと TypeScript の型チェックが弱くなる。

TypeScript のメリットは「型でミスを防げること」なので、any を多用すると JavaScript に近くなってしまう。基本的には、できるだけ具体的に `string[]` `number[]` `boolean[]` のように型を書く方がよい。

## 4. ユニオン型について学んだ

ユニオン型は、`|` を使って 複数の型を許可する型。

```ts
function combine(input1: number | string, input2: number | string) {
  let result;
  if (typeof input1 === "number" && typeof input2 === "number") {
    result = input1 + input2;
  } else {
    result = input1.toString() + input2.toString();
  }
  return result;
}
```

`number | string` は、number または string という意味。そのため、次のように数値も文字列も渡せる。

```ts
const combinedAges = combine(30, 26);
console.log(combinedAges); // 56

const combinedNames = combine("Max", "Anna");
console.log(combinedNames); // "MaxAnna"
```

## 5. toString() の役割を確認した

`result = input1.toString() + input2.toString();` は、input1 と input2 を 文字列に変換してから結合する という意味。

例えば、`30.toString()` のようにすると、数値の 30 が文字列の "30" になる。

## 6. リテラル型について学んだ

リテラル型は、特定の値だけを許可する型。

```ts
function combine(
  input1: number | string,
  input2: number | string,
  resultConversion: "as-number" | "as-text",
) {
  let result;
  if (
    (typeof input1 === "number" && typeof input2 === "number") ||
    resultConversion === "as-number"
  ) {
    result = +input1 + +input2;
  } else {
    result = input1.toString() + input2.toString();
  }
  return result;
}
```

ここでは、`resultConversion: "as-number" | "as-text"` としている。これは、resultConversion には "as-number" または "as-text" しか入れられないという意味。ただの string ではない。

```ts
combine(30, 26, "as-number"); // OK
combine("Max", "Anna", "as-text"); // OK
combine(30, 26, "number"); // エラー
```

## 7. "as-number" の as- は決まりではない

"as-number" の as- は TypeScript の決まりではなく、教材側が分かりやすくするためにつけた名前。そのため、`resultConversion: "number" | "text"` のようにしてもよい。ただし、その場合は条件式も合わせる必要がある。

## 8. +input1 の意味を学んだ

`result = +input1 + +input2;` の +input1 は、文字列を数値に変換する書き方。例えば、`+"30"` は、文字列の "30" を数値の 30 に変換する。

## 9. 型エイリアスについて学んだ

型エイリアスは、型に名前をつける仕組み。

```ts
type Combinable = number | string;
type ConversionDescriptor = "as-number" | "as-text";

function combine(
  input1: Combinable,
  input2: Combinable,
  resultConversion: ConversionDescriptor,
) {
  let result;
  if (
    (typeof input1 === "number" && typeof input2 === "number") ||
    resultConversion === "as-number"
  ) {
    result = +input1 + +input2;
  } else {
    result = input1.toString() + input2.toString();
  }
  return result;
}
```

型エイリアスを使うことで、長い型を何度も書かなくてよくなり、コードが読みやすくなる。
