## 2. watch モードの理解

watch モードは、TypeScript ファイルの変更を監視し、保存のたびに自動コンパイルしてくれる機能。

通常は毎回以下を実行する必要がある。

```bash
tsc app.ts
```

watch を使うと以下で自動化できる。

```bash
tsc -w
```

---

## 3. 生成ファイルが増える理由

tsc や tsc -w を実行すると、.ts から .js が生成される。
tsconfig.json の設定によっては、次のファイルも生成される。

```txt
app.ts        // 自分が書く TypeScript
app.js        // 生成された JavaScript
app.d.ts      // 型定義ファイル
app.js.map    // デバッグ用マップファイル
app.d.ts.map  // 型定義のマップファイル
```

学習初期は、sourceMap や declaration の設定を見直すと生成物を減らせる。

## 4. 発生したエラーと原因

ブラウザ実行時に以下のエラーが出た。

```txt
Uncaught SyntaxError: Unexpected token 'export'
```

原因は、TypeScript の出力が ES Modules 形式だったのに、HTML 側で通常 script として読み込んでいたこと。

生成された app.js / analytics.js には次が含まれていた。

```js
export {};
```

export は「モジュールとして読み込む前提」の構文なので、通常 script だと文法エラーになる。

## 5. module 設定の学び

最終的に次の理解に到達した。

- module は「TypeScript をどの JavaScript 形式に変換するか」を決める。
- script type="module" は「ブラウザがその JavaScript をどう読むか」を決める。

つまり、次の2つをセットで揃える必要がある。

```json
"module": "ES6"
```

```html
<script type="module" src="app.js"></script>
<script type="module" src="analytics.js"></script>
```

## 6. 実務・今後への接続

TypeScript はフロントエンドだけでなく、Node.js / Express などバックエンドでも使える。

```txt
TypeScript
↓ コンパイル
JavaScript
↓
ブラウザ または Node.js で実行
```

大事なのは「どこで動かす JavaScript か」を意識して tsconfig を決めること。
