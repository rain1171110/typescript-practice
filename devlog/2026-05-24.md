# 2026年5月24日 学習ログ

今日は、TypeScript の `tsconfig.json` を中心に、`.ts` ファイルがどのように `.js` に変換され、ブラウザで読み込まれるのかを学習した。

特に、`app.ts` や `analytics.ts` を作成し、それらを `tsc` でコンパイルして `dist` フォルダに JavaScript ファイルとして出力する流れを確認した。

---

## 1. include / exclude / files の違い

### include

```json
"include": ["app.ts", "analytics.ts"]
```

これは、指定したファイルをコンパイル対象にする設定。

- `app.ts` : コンパイル対象
- `analytics.ts` : コンパイル対象
- `other.ts` : 対象外

また、以下のように書けば `src` フォルダ内の `.ts` ファイルをまとめて対象にできる。

```json
"include": ["src/**/*.ts"]
```

### exclude

```json
"exclude": ["node_modules"]
```

これは、コンパイル対象から外すフォルダやファイルを指定する設定。

`node_modules` は大量のライブラリが入っているため、通常はコンパイル対象にしない。
なお、`node_modules` は何も書かなくても基本的にデフォルトで除外される。

### files

```json
"files": ["app.ts"]
```

これは、コンパイルするファイルを完全に指定する設定。

この場合、`app.ts` だけが対象になる。

- `app.ts` : コンパイル対象
- `analytics.ts` : 対象外

`analytics.ts` も使いたい場合は、`files` に追加する必要がある。

```json
"files": ["app.ts", "analytics.ts"]
```

普段は `files` よりも `include` の方が使いやすい。

## 2. lib の理解

今回は次の設定について学習した。

```json
"lib": ["DOM", "ES6", "DOM.Iterable", "ScriptHost"]
```

これは、TypeScript に「どの環境の型情報を使わせるか」を指定する設定。

今回のコードでは、以下のようなブラウザ機能を使っていた。

```ts
const button = document.querySelector("button")!;

button.addEventListener("click", () => {
  console.log("Clicked");
});
```

この中の `document`、`querySelector`、`addEventListener`、`console` などはブラウザが持っている機能。
そのため、`lib` に `DOM` が入っていないと、TypeScript がそれらを理解できないことがある。

### DOM

```json
"DOM"
```

HTML を JavaScript から操作するための型情報。

### ES6

```json
"ES6"
```

ES6 の JavaScript 機能の型情報を使えるようにする設定。

`target` の `ES6` とは意味が違う。

```json
"target": "ES6"
```

これは「どのバージョンの JavaScript に変換するか」。

```json
"lib": ["ES6"]
```

これは「どの JavaScript 機能の型情報を使えるようにするか」。

### DOM.Iterable

```json
"DOM.Iterable"
```

DOM 関連の複数要素を `for...of` などで扱いやすくするための型情報。

```ts
const buttons = document.querySelectorAll("button");

for (const button of buttons) {
  console.log(button);
}
```

## 3. `!` の意味（non-null assertion）

```ts
const button = document.querySelector("button")!;
```

この `!` は「この値は `null` ではない」と TypeScript に伝える記法。

`querySelector` は、対象要素がなければ `null` を返す可能性がある。
そのため本来は、`button` は `null` かもしれないと TypeScript が判断する。

ただし、実際に HTML に `<button>` が存在しないと実行時エラーになる可能性がある。
より安全に書くなら以下のようにする。

```ts
const button = document.querySelector("button");

if (button) {
  button.addEventListener("click", () => {
    console.log("Clicked");
  });
}
```

## 4. 404 Not Found エラーの分析

ブラウザで次のエラーが出た。

```txt
GET http://localhost:3000/dist/app.js net::ERR_ABORTED 404 (Not Found)
GET http://localhost:3000/dist/analytics.js net::ERR_ABORTED 404 (Not Found)
```

これは、`index.html` が `/dist/app.js` と `/dist/analytics.js` を読みに行ったが、その場所にファイルが存在しないという意味。

### 原因

実際の出力先が次のようになっていた。

```txt
dist/
	src/
		app.js
		analytics.js
```

つまり実ファイルは `dist/src/app.js` と `dist/src/analytics.js`。

しかし、`index.html` は次のように読みに行っていた。

```html
<script type="module" src="./dist/app.js"></script>
<script type="module" src="./dist/analytics.js"></script>
```

このズレで 404 になった。

## 5. rootDir と outDir

次の設定が重要だった。

```json
"rootDir": "./src",
"outDir": "./dist"
```

意味は以下の通り。

- `rootDir: ./src` : `src` の中身を基準にする
- `outDir: ./dist` : 変換後の JavaScript を `dist` に出す

これにより、`src/app.ts` が `dist/app.js` として出力される。

## 6. removeComments と JSON 構文エラー

```json
"removeComments": true
```

これは、TypeScript を JavaScript に変換するときにコメントを削除する設定。

ただし、以下のように書くと JSON 構文エラーになる。

```json
"removeComments": true
"target": "ES6"
```

項目と項目の間にカンマが必要なので、正しくはこう。

```json
"removeComments": true,
"target": "ES6"
```

## 7. noEmitOnError

```json
"noEmitOnError": true
```

TypeScript のエラーがある場合、JavaScript ファイルを出力しない設定。

例えば型エラーがあると、`dist/app.js` は更新されない。

```ts
let userName: string;
userName = 123;
```

そのため、ブラウザ表示が変わらないときは `tsc` のエラー確認が必要。

---

## 8. noImplicitAny と strict

```json
"noImplicitAny": true
```

型を判断できないときに暗黙的に `any` になることを禁止する設定。

```ts
function add(num1, num2) {
  return num1 + num2;
}
```

上のようなコードはエラーになり、次のように型注釈が必要。

```ts
function add(num1: number, num2: number) {
  return num1 + num2;
}
```

`any` は何でも入れられる便利さがある一方で、型安全を弱める。
そのため、暗黙の `any` を防ぐことが重要。

また、`strict: true` には `noImplicitAny: true` も含まれている。

---

## 9. 今日の最終理解

TypeScript の基本フローは以下。

```txt
src/app.ts
src/analytics.ts
↓
tsc
↓
dist/app.js
dist/analytics.js
↓
index.html で読み込む
↓
ブラウザで実行される
```

ポイントは、`.ts` を直接ブラウザで動かすのではなく、まず `.js` に変換し、その JavaScript を HTML から読み込むこと。

---

## 今日の重要ポイントまとめ

- `"rootDir": "./src"` : `src` の中身を基準にする
- `"outDir": "./dist"` : 変換後の JavaScript を `dist` に出す
- `"include": ["src/**/*.ts"]` : `src` 内の `.ts` を対象にする
- `"lib": ["DOM", "ES6", "DOM.Iterable", "ScriptHost"]` : ブラウザや ES6 の型情報を使えるようにする
- `"removeComments": true` : 出力 JavaScript からコメントを削除する
- `"noEmitOnError": true` : TypeScript エラー時は JavaScript を出力しない
- `"noImplicitAny": true` : 暗黙の `any` を禁止する
- `"strict": true` : 厳しめの型チェックをまとめて有効にする
