## 3. コードを1行ずつ説明する枠

```ts
const add = (...numbers: number[]) => {
  return numbers.reduce((curResult, curValue) => {
    return curResult + curValue;
  }, 0);
};

const addedNumbers = add(5, 10, 2, 3.7);

const [hobby1, hobby2, ...remainingHobbies] = hobbies;
const { firstName: userName, age } = person;

class Department {
  name: string;

  constructor(n: string) {
    this.name = n;
  }
}

const accounting = new Department("Accounting");
```

- `...numbers: number[]`: 複数の引数を配列として受け取る。配列の中身は number 型に限定される。
- `reduce(..., 0)`: 配列の先頭から順に足し合わせ、最終的に 1 つの値にまとめる。
- `add(5, 10, 2, 3.7)`: 関数内では `numbers = [5, 10, 2, 3.7]` として扱われる。
- `[hobby1, hobby2, ...remainingHobbies]`: 先頭から順に取り出し、残りは配列で受け取る。
- `{ firstName: userName, age }`: `person.firstName` を `userName` という別名で取り出す。
- `class Department`: オブジェクト生成の設計図を定義する。
- `constructor(n: string)`: `new` 時に自動で呼ばれる初期化処理。
- `this.name = n`: 今まさに生成中のインスタンスに値をセットする。

## 4. テンプレートに取り込める学びの枠

- 命名ルール: 分割代入で別名をつけるときは、用途が伝わる名前にする（例: `firstName` → `userName`）。
- データ更新ルール: Rest 構文は「引数をまとめる」「残りをまとめる」の2パターンで使い分ける。
- API設計ルール: 可変長引数を受ける関数は `(...args: 型[])` の形で設計すると再利用しやすい。
- エラー処理ルール: オブジェクト分割代入で別名をつけた場合、元のプロパティ名の変数は直接使えない点を意識する。

## 6. つまずきと対策の枠

- つまずいたこと: `this` が最初から `accounting` を指しているように感じて混乱した。
- 原因: 変数への代入タイミング（生成後）と、constructor 実行中の参照先（生成中インスタンス）を分けて考えられていなかった。
- 対策: `new` の内部ステップ（生成 → constructor 実行 → 代入）を順番で整理した。
- 次回の予防: class を書くときは「this は生成中インスタンス」を毎回言語化して確認する。
