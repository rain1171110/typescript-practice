## 3. 実装の要点（理解を深める）

```ts
class Department {
  name: string;

  constructor(n: string) {
    this.name = n;
  }

  describe(this: Department) {
    console.log("Department:" + this.name);
  }
}

const accounting = new Department("Accounting");
accounting.describe();

const accountingCopy = { describe: accounting.describe };
accountingCopy.describe();
```

- このコードの責務（1文）: `Department` インスタンスの初期化と、`this` を使った状態表示を行う
- 入力: `new Department("Accounting")` の引数 `"Accounting"`
- 出力: `accounting.describe()` で `Department:Accounting` を出力
- 副作用（ある場合）: `console.log` による標準出力
- 型で守れていること: `name` と `n` が `string`、`describe(this: Department)` によりメソッド内 `this` の型が保証される
- 改善余地（命名/分割/重複/境界条件）: `accountingCopy` のような切り出し呼び出し時の `this` 崩れを防ぐ実装（bind など）の整理を次回追加

## 5. つまずきから学ぶ（再発防止まで）

- つまずいた現象: `describe()` 内の `this` がなぜ `accounting` になるか分からなかった
- 直接原因: `this` を「変数名で固定される参照」と誤解していた
- 根本原因（思考・知識・確認不足のどれか）: 知識不足（メソッド呼び出し時の `this` ルール）
- 切り分け手順（次回使える手順化）:
  1. メソッド呼び出し式を確認する
  2. ドット左側のオブジェクトを特定する
  3. メソッド内 `this` をそのオブジェクトに置き換えて読む
  4. `new` の流れ（生成 -> constructor -> 代入）で初期化を再確認する
- 再発防止ルール（チェック項目にする）: `this` が出たら「今どの呼び出し式で実行されているか」を先に確認する
