## 3. 実装の要点（理解を深める）

```ts
class Department {
  name: string;
  private employees: string[] = [];

  constructor(n: string) {
    this.name = n;
  }

  describe(this: Department) {
    console.log("Department:" + this.name);
  }

  addEmployee(employee: string) {
    this.employees.push(employee);
  }

  printEmployeeInformation() {
    console.log(this.employees.length);
    console.log(this.employees);
  }
}

const accounting = new Department("Accounting");

accounting.addEmployee("Max");
accounting.addEmployee("Manu");

// accounting.employees[2] = "Anna";
accounting.name = "NEW NAME";

accounting.describe();
accounting.printEmployeeInformation();
```

- このコードの責務（1文）: 部署オブジェクトの状態を class で管理し、従業員データをメソッド経由で安全に操作する
- 入力: `new Department("Accounting")` の文字列、`addEmployee("Max")` などの従業員名
- 出力: `describe()` と `printEmployeeInformation()` のコンソール出力
- 副作用（ある場合）: `employees` 配列への追加、`console.log` 出力
- 型で守れていること: `name` と `employee` は `string`、`employees` は `string[]`
- 改善余地（命名/分割/重複/境界条件）: 空文字や重複名の追加をどう扱うかのルールを追加するとより実務的

## 5. つまずきから学ぶ（再発防止まで）

- つまずいた現象: class 関連の用語と役割（`class`, `constructor`, `this`, `private`, `employees`, `accounting`）が頭の中で混ざる
- 直接原因: 「コード上の名前」と「実行中に指している実体（オブジェクト）」を分けて考えられていなかった
- 根本原因（思考・知識・確認不足のどれか）: 知識不足 + 整理不足
- 切り分け手順（次回使える手順化）:
  1. まず `new Department("Accounting")` で何が作られるかを言葉にする
  2. `this.name = n` の `this` を `accounting` に置き換えて読む
  3. `accounting.addEmployee("Max")` を見て、メソッド内 `this` も `accounting` として追う
  4. `private` は「外部直接操作NG、内部メソッド経由OK」として整理する
- 再発防止ルール（チェック項目にする）: `this` が出たら「どのオブジェクトがこのメソッドを呼んだか」を必ず先に確認する
