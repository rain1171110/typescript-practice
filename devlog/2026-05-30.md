## 3. 実装の要点（理解を深める）

```ts
class Department {
  name: string;
  private employees: string[] = [];

  constructor(n: string) {
    this.name = n;
  }

  addEmployee(employee: string) {
    this.employees.push(employee);
  }
}

const accounting = new Department("Accounting");
accounting.addEmployee("Max");
```

- このコードの責務（1文）: 部署オブジェクトを作成し、従業員名をメソッド経由で追加する
- 入力: `new Department("Accounting")` の `"Accounting"`、`addEmployee("Max")` の `"Max"`
- 出力: 直接の戻り値はないが、`employees` 配列の状態が更新される
- 副作用（ある場合）: `employees` 配列が `push` で変更される
- 型で守れていること: `name` と `employee` は `string`、`employees` は `string[]`
- 改善余地（命名/分割/重複/境界条件）: 空文字や重複名を弾くバリデーションを `addEmployee` に追加できる

## 5. つまずきから学ぶ（再発防止まで）

- つまずいた現象: `accounting.addEmployee("Max")` で `employee` に `accounting` が入ると誤解した
- 直接原因: 「メソッドを実行する主体」と「メソッドに渡すデータ」を同じものとして見ていた
- 根本原因（思考・知識・確認不足のどれか）: 整理不足
- 切り分け手順（次回使える手順化）:
  1. 呼び出し式のドット左側を確認する（`accounting`）
  2. そのメソッド内 `this` をドット左側に置換する
  3. 括弧内の値を引数に対応させる（`employee = "Max"`）
  4. `this.employees.push(employee)` を具体化して読む（`accounting.employees.push("Max")`）
- 再発防止ルール（チェック項目にする）: メソッド呼び出しを見たら「`this` と引数は別役割」を先にメモする
