## 3. 実装の要点（理解を深める）

```ts
class Department {
  constructor(
    private readonly id: string,
    public name: string,
  ) {}

  private employees: string[] = [];

  addEmployee(employee: string) {
    if (employee === "") {
      return;
    }
    this.employees.push(employee);
  }

  printEmployeeInformation() {
    console.log(this.employees.length);
    console.log(this.employees);
  }
}

class ITDepartment extends Department {
  constructor(
    id: string,
    public admins: string[],
  ) {
    super(id, "IT");
  }
}
```

- このコードの責務（1文）: 部署オブジェクトを型安全に初期化し、従業員データを制御された入口から更新する
- 入力: `new ITDepartment("d1", ["Max"])` の `id` と `admins`、`addEmployee("Max")` などの従業員名
- 出力: 直接の戻り値はないが、`employees` 配列が更新され `printEmployeeInformation()` で件数と一覧を確認できる
- 副作用（ある場合）: `addEmployee()` により `employees` の内部状態が変化する
- 型で守れていること: `id` は `readonly` で再代入不可、`employees` は `string[]` のみ、`private` で外部直接操作不可
- 改善余地（命名/分割/重複/境界条件）: `employee.trim() === ""` の判定にして空白入力も防ぐ

## 5. つまずきから学ぶ（再発防止まで）

- つまずいた現象: `admins` を `private` で定義した際に未使用エラーの意味を取り違えた
- 直接原因: `private` の可視性と「クラス内で実際に読まれているか」の判定を分けて考えられていなかった
- 根本原因（思考・知識・確認不足のどれか）: 確認不足
- 切り分け手順（次回使える手順化）:
  1. エラーメッセージが「型エラー」か「未使用警告」かを先に分類する
  2. 該当プロパティがクラス内で読み書きされているか検索する
  3. `private` / `public` は「見える範囲」、未使用判定は「使われた回数」と分離して判断する
  4. 使う予定がないなら削除、使うならメソッド内で参照する
- 再発防止ルール（チェック項目にする）: 新しいプロパティを追加したら「どこで読むか」を同時に1か所書く
