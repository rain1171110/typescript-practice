## 学習内容

### 1. `extends` の理解

`ITDepartment extends Department` の意味を確認した。

```ts
class ITDepartment extends Department
```

これは、`ITDepartment` が `Department` の機能を引き継ぐという意味。

`Department` にある以下のメソッドを、`ITDepartment` 側に書かなくても使える。

```ts
describe();
addEmployee();
printEmployeeInformation();
```

理解したこと：

- `extends` は型定義のためではない
- 親クラスのデータやメソッドを子クラスで再利用するため
- React の「親に処理を書いて子で使う」感覚に少し似ている
- ただし React は props で渡す、class 継承は親の機能を引き継ぐ、という違いがある

---

### 2. `super()` の理解

子クラスの constructor で使う `super()` について確認した。

```ts
constructor(id: string, admins: string[]) {
  super(id, "IT");
  this.admins = admins;
}
```

`new ITDepartment("d1", ["Max"])` を実行すると、

```ts
id = "d1";
admins = ["Max"];
```

になる。

そのあと、

```ts
super(id, "IT");
```

によって親クラス `Department` の constructor に値を渡す。

親クラス側では、

```ts
id = "d1";
name = "IT";
```

として扱われる。

理解したこと：

- `super()` は親クラスの constructor を呼ぶ
- `super(id, "IT")` は親に `id` と `"IT"` を渡している
- `"d1"` は `new ITDepartment("d1", ["Max"])` から来ている

### 3. `private` と `protected` の違い

最初は `employees` を `private` にしていた。

```ts
private employees: string[] = [];
```

これは、親クラス `Department` の中だけで使える。

その後、`protected` に変更した。

```ts
protected employees: string[] = [];
```

`protected` にすると、外からは触れないが、子クラスからは触れる。

```ts
this.employees.push(name);
```

理解したこと：

- `private` は親クラスの中だけ
- `protected` は親クラスと子クラスの中で使える
- 外部から `it.employees` のようには触れない
- 便利だが、子クラスから直接変更できるため、設計が脆くなる可能性もある

### 4. オーバーライドの理解

`AccountingDepartment` で親クラスの `addEmployee()` を上書きした。

親クラス：

```ts
addEmployee(employee: string) {
  this.employees.push(employee);
}
```

子クラス：

```ts
addEmployee(name: string) {
  if (name === "Max") {
    return;
  }
  this.employees.push(name);
}
```

これにより、`AccountingDepartment` では `"Max"` は追加されず、`"Mai"` だけ追加される。

理解したこと：

- 子クラスで親と同じ名前のメソッドを書くと上書きできる
- これをオーバーライドという
- 共通処理は親に置き、特定のクラスだけルールを変えたいときに使える

---

### 5. `protected` の設計上の注意

`protected` は便利だが、子クラスが親のデータを直接変更できる。

そのため、より安全にするなら `employees` は `private` のままにして、子クラスでは親のメソッドを呼ぶ方法もある。

```ts
super.addEmployee(name);
```

理解したこと：

- 基本は `private` の方が安全
- 子クラスから直接触る必要があるときだけ `protected` を使う
- `protected` はセキュリティ対策ではなく、設計上の制御
- TypeScript の `private` / `protected` は開発中にミスを防ぐためのルールに近い

### 6. 配列アクセスと `undefined` のエラー

以下のエラーを確認した。

```ts
Type 'string | undefined' is not assignable to type 'string'.
```

原因はこれ。

```ts
this.lastReport = reports[0];
```

`reports` が空配列の場合、

```ts
reports[0];
```

は `undefined` になる。

しかし、

```ts
private lastReport: string;
```

は `string` しか受け取れないため、TypeScript がエラーを出した。

一時的に以下のように書いて対応した。

```ts
this.lastReport = reports[0]!;
```

理解したこと：

- `reports[0]` は `string | undefined` になる可能性がある
- `!` は「undefined ではないと TypeScript に伝える」記号
- ただし実行時に本当に `undefined` でなくなるわけではない
- 空配列なら中身は `undefined` のまま

### 7. getter の理解

`get mostRecentReport()` を使った。

```ts
get mostRecentReport() {
  if (this.lastReport) {
    return this.lastReport;
  }
  throw new Error("レポートが見つかりません");
}
```

呼び出しは関数のようにしない。

```ts
console.log(accounting.mostRecentReport);
```

これは getter が呼ばれている。

理解したこと：

- `get` は値を読むときに動く
- 呼び出すときは `()` を付けない
- 普通のプロパティのように見えるが、裏では処理が動いている
- `lastReport` がない場合はエラーを投げることができる

---

### 8. setter の理解

`set mostRecentReport()` を使った。

```ts
set mostRecentReport(value: string) {
  if (!value) {
    throw new Error("正しい値を設定してください。");
  }
  this.addReport(value);
}
```

以下のように代入すると、setter が呼ばれる。

```ts
accounting.mostRecentReport = "通期会計レポート";
```

これは裏で、

```ts
this.addReport("通期会計レポート");
```

を呼んでいる。

理解したこと：

- `set` は値を代入するときに動く
- setter の中でバリデーションできる
- 今回は空文字など不正な値ならエラーを出す
- 正しい値なら `addReport()` を呼び、`reports` と `lastReport` を更新する

```ts
  }

  }
  this.addReport(value);
}
```

このコードで、

```ts
accounting.mostRecentReport = "通期会計レポート";
```

は setter を呼び、

```ts
console.log(accounting.mostRecentReport);
```

は getter を呼ぶ。

## 今日の理解まとめ

今日のポイントは以下。

`extends`

親クラスの機能を子クラスで使えるようにする。

`super()`

親クラスの constructor を呼ぶ。

`protected`

外からは触れないが、子クラスからは触れる。

`override`

子クラスで親クラスのメソッドを上書きする。

`get`

値を読むときに処理を動かす。

`set`

値を代入するときに処理を動かす。

## 感想・気づき

JavaScript で理解したつもりだった `this`、関数、オブジェクト、引数の考え方が、TypeScript の class で再び出てきて難しく感じた。

ただ、今日は以下のように整理できた。

```text
親クラス = 共通部分
子クラス = 専用部分
extends = 親の機能を引き継ぐ
super = 親の constructor を呼ぶ
this = 今作られている、または今メソッドを呼んでいるオブジェクト
```

特に、`get` と `set` については、普通のプロパティに見えるが、裏でメソッドのように処理が動いていることを確認できた。
