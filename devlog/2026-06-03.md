## 学習内容

### 1. `super(id, "IT")` の意味

```ts
super(id, "IT");
```

の `"IT"` は、親クラス `Department` の `name` に渡す **部署名の文字列**。

一方で、

```ts
const it = new ITDepartment("d1", ["Max"]);
```

の `it` は、作成した `ITDepartment` のインスタンスを入れる **変数名**。

つまり、

```ts
it;
```

はオブジェクトを操作するための名前。

```ts
"IT";
```

はオブジェクトの中に保存される部署名。

この2つは別物。

---

### 2. `static` の使い方

```ts
static fiscalYear = 2020;

static createEmployee(name: string) {
  return { name: name };
}
```

`static` がついたものは、インスタンスではなく **クラスそのもの**に属する。

そのため、

```ts
Department.fiscalYear;
Department.createEmployee("Max");
```

のように、クラス名から呼び出す。

一方で、

```ts
this.fiscalYear;
it.fiscalYear;
```

のように、インスタンス側からは使えない。

今日の理解：

```text
static がついているもの
→ Department.〇〇 で呼ぶ

static がついていないもの
→ it.〇〇 / accounting.〇〇 で呼ぶ
```

### 3. `protected readonly id` の理解

最初は `private readonly id` だったが、子クラスの中で `this.id` を使うために、

```ts
protected readonly id: string
```

に変更した。

`protected` は以下の通り。

| 場所         | 使えるか |
| ------------ | -------- |
| 親クラスの中 | OK       |
| 子クラスの中 | OK       |
| 外側から     | NG       |

そのため、子クラス `ITDepartment` や `AccountingDepartment` の中では、

```ts
this.id;
```

を使える。

### 4. `describe()` のオーバーライド

親クラスにある `describe()` を、子クラスで同じ名前で書くと、子クラス側の処理が優先される。

```ts
class ITDepartment extends Department {
  describe() {
    console.log("IT部門 - ID: " + this.id);
  }
}
```

```ts
class AccountingDepartment extends Department {
  describe() {
    console.log("会計部門- ID: " + this.id);
  }
}
```

このようにすると、

```ts
it.describe();
```

では IT部門用の `describe()` が動く。

```ts
accounting.describe();
```

では会計部門用の `describe()` が動く。

### 5. `abstract class` の理解

今日の最後に、

```ts
abstract class Department
```

を学習した。

`abstract class` は、

> 共通の親クラスとして使うが、直接 `new Department()` はできないクラス

という意味。

つまり `Department` は、IT部門や会計部門の共通部分をまとめるための土台。

---

### 6. `abstract describe(this: Department): void;`

```ts
abstract describe(this: Department): void;
```

これは、

> 子クラスは必ず `describe()` を作りなさい

というルール。

親クラスでは中身を書かない。

```ts
abstract describe(this: Department): void;
```

だけを書く。

その代わり、子クラス側で必ず実装する。

```ts
describe() {
  console.log("IT部門 - ID: " + this.id);
}
```

```ts
describe() {
  console.log("会計部門- ID: " + this.id);
}
```

## 今日の重要な整理

### Department 由来のもの

```text
id
name
employees
addEmployee()
printEmployeeInformation()
static fiscalYear
static createEmployee()
```

`Department` は、部署に共通する機能を持つ。

ただし `abstract class` にしたので、直接インスタンス化はしない。

---

### ITDepartment 専用のもの

```text
admins
describe()
```

IT部門は、親クラスの機能を引き継ぎつつ、自分専用の `admins` と `describe()` を持つ。

---

### AccountingDepartment 専用のもの

```text
reports
lastReport
mostRecentReport getter
mostRecentReport setter
addReport()
printReports()
addEmployee()
describe()
```

会計部門は、レポート機能を持ち、さらに `addEmployee()` を独自ルールで上書きしている。

```ts
addEmployee(name: string) {
  if (name === "Max") {
    return;
  }
  this.employees.push(name);
}
```

そのため、`Max` は追加されず、`Mai` だけ追加される。

## 今日の理解ポイント

今日の一番大事な理解はこれ。

```ts
abstract class Department
```

は、

> 共通機能を持つ親クラス。直接 new しない。

```ts
abstract describe(): void;
```

は、

> 子クラスに describe の実装を強制する。

```ts
static;
```

は、

> インスタンスではなくクラス側にあるもの。

```ts
protected;
```

は、

> 親クラスと子クラスの中では使えるが、外からは触れないもの。

```ts
super(id, "IT");
```

は、

> 親クラスの constructor に id と name を渡している。
