## 1. abstract class の復習

`abstract class Department` は、直接インスタンスを作らせないための親クラス。

```ts
abstract class Department {
  constructor(
    protected readonly id: string,
    public name: string,
  ) {}
}
```

`Department` は「部門」という広い概念なので、

```ts
new Department();
```

のように直接作るのは自然ではない。

実際には、

```ts
ITDepartment;
AccountingDepartment;
```

のような具体的な子クラスからインスタンスを作る。

理解したこと：

```text
abstract class
= 親クラスを直接 new させないための設計図
```

---

## 2. abstract describe() の復習

```ts
abstract describe(this: Department): void;
```

これは、親クラスに処理を書くためではなく、子クラスに必ず `describe()` を実装させるためのルール。

つまり `Department` は、

```text
describe() というメソッドは必ず作ってください。
ただし、中身は子クラスごとに決めてください。
```

と言っている。

理解したこと：

```text
abstract method
= 子クラスに必ず実装させるメソッド
```

---

## 3. シングルトンパターン

シングルトンとは、インスタンスを1つだけに制限する設計パターン。

今回の例では、`AccountingDepartment` を1つだけ作るようにした。

```ts
const accounting = AccountingDepartment.getInstance();
const accounting2 = AccountingDepartment.getInstance();
```

この2つは別々のオブジェクトではなく、同じ1つの `AccountingDepartment` インスタンスを指す。

確認するなら、

```ts
console.log(accounting === accounting2);
```

これは `true` になる。

---

## 4. private static instance

```ts
private static instance: AccountingDepartment;
```

これは、作成済みの `AccountingDepartment` インスタンスを保存しておく場所。

`static` がついているので、インスタンス側ではなくクラス側にある。

イメージ：

```ts
AccountingDepartment.instance;
```

理解したこと：

```text
private static instance
= 作った1つのインスタンスをクラス側に保存しておく箱
```

## 5. private constructor

```ts
private constructor(
  id: string,
  private reports: string[],
) {
  super(id, "Accounting");
  this.lastReport = reports[0]!;
}
```

`constructor` に `private` をつけると、クラスの外から `new` できなくなる。

そのため、これはエラーになる。

```ts
const accounting = new AccountingDepartment("d2", []);
```

ただし、クラスの中からは `new AccountingDepartment()` できる。

理解したこと：

```text
private constructor
= 外から勝手に new させない
= クラスの中からだけ new できる
```

## 6. getInstance() の役割

```ts
static getInstance() {
  if (AccountingDepartment.instance) {
    return this.instance;
  }
  this.instance = new AccountingDepartment("d2", []);
  return this.instance;
}
```

`getInstance()` は、`AccountingDepartment` のインスタンスを取得するための入口。

流れはこう。

```text
1回目の getInstance()
→ instance がまだない
→ new AccountingDepartment() で作る
→ instance に保存して返す

2回目以降の getInstance()
→ すでに instance がある
→ 新しく作らず、保存済みの同じ instance を返す
```

理解したこと：

```text
getInstance()
= なければ作る
= あれば同じものを返す
```

---

## 7. this.instance について

`getInstance()` は `static` メソッドなので、その中の `this` はインスタンスではなく、基本的にクラス自身を指す。

つまり、

```ts
this.instance;
```

は、この例ではだいたい

```ts
AccountingDepartment.instance;
```

と考えてよい。

初心者のうちは、こちらの書き方の方が理解しやすい。

```ts
static getInstance() {
  if (AccountingDepartment.instance) {
    return AccountingDepartment.instance;
  }

  AccountingDepartment.instance = new AccountingDepartment("d2", []);
  return AccountingDepartment.instance;
}
```

## 8. 今日の重要ポイント

今日の一番大事な理解はこれ。

```text
abstract class
= 直接 new させない親クラス

abstract method
= 子クラスに必ず実装させるメソッド

private constructor
= 外から new させない

static getInstance()
= クラスから直接呼び出して、インスタンスを取得する入口

singleton
= 1個だけ作って、それを使い回す仕組み
```

## 今日のまとめ

今日は、`abstract class Department` から始まり、`AccountingDepartment` のシングルトンまで学習した。

`Department` は広すぎる概念なので、直接 `new` するのではなく、具体的な子クラスからインスタンスを作る方が自然だと理解した。

また、`abstract describe()` は親クラスで中身を書くものではなく、子クラスに `describe()` を必ず作らせるためのルールだと理解した。

シングルトンでは、`private constructor` によって外から `new AccountingDepartment()` できないようにし、代わりに `static getInstance()` を使ってインスタンスを取得する。

その結果、`AccountingDepartment` は1つだけ作られ、2回目以降は同じインスタンスが返される。

今日の結論：

```text
シングルトンは、
「1個だけ作って、それをみんなで使い回す」ための書き方。
```
