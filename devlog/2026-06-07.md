# 2026-06-07 学習ログ

## 今日のテーマ

TypeScript の `interface` / `type` / `implements` / optional property の整理

## 学習内容

今日は TypeScript の `interface` と `type` について学習した。

まず、`type AddFn = (a: number, b: number) => number;` のように、関数の型に名前をつける書き方を復習した。
これは「number を2つ受け取り、number を返す関数」というルールを `AddFn` という名前で定義している。

次に、同じ関数の型を `interface` でも書けることを学習した。

```
interface AddFn {
  (a: number, b: number): number;
}
```

この書き方は少し特殊で、プロパティ名を書かずに `(a: number, b: number): number;` と書くことで、「呼び出せるもの」、つまり関数の型を表している。

また、`interface Named` と `interface Greetable extends Named` を使って、interface が別の interface を継承できることも学習した。

```
interface Named {
  readonly name?: string;
  outputName?: string;
}

interface Greetable extends Named {
  greet(phrase: string): void;
}
```

`Greetable extends Named` と書くことで、`Greetable` は `Named` の内容も引き継ぐ。
つまり、`Greetable` を実装するクラスは、`greet()` を持つ必要があり、さらに `Named` 側の `name` や `outputName` のルールも関係する。

今回は `name?: string` のように `?` がついていたため、`name` は「あってもなくてもよい」という意味になる。
そのため、`Person` クラスでは `name` を必ず持たせる必要はなく、`new Person()` のように名前なしでもインスタンスを作ることができた。

```
class Person implements Greetable {
  name?: string;
  age = 30;

  constructor(n?: string) {
    if (n) {
      this.name = n;
    }
  }

  greet(phrase: string) {
    if (this.name) {
      console.log(phrase + " " + this.name);
    } else {
      console.log("Hi!");
    }
  }
}
```

`constructor(n?: string)` の `?` は、引数 `n` を渡してもいいし、渡さなくてもいいという意味。
そのため、`new Person("Max")` も `new Person()` も使える。

今回は `new Person()` として名前を渡さなかったので、`this.name` は設定されず、`greet()` の中では `else` に入り、`Hi!` が出力される。

```
let user1: Greetable;

user1 = new Person();

user1.greet("Hello I am");
console.log(user1);
```

出力イメージは以下のようになる。

```
3
Hi!
Person { age: 30 }
```

## 今日理解したこと

- `type` は型に名前をつけられる
- `type AddFn = (a: number, b: number) => number;` は関数の型を表す
- `interface` でも関数の型を書ける
- `interface AddFn { (a: number, b: number): number; }` は「呼び出せる関数の形」を表す
- `interface` は別の `interface` を `extends` できる
- `class Person implements Greetable` は、Person クラスが Greetable のルールを守るという意味
- `readonly name` は、あとから変更できない読み取り専用プロパティ
- `name?: string` は、name があってもなくてもよいという意味
- `constructor(n?: string)` は、引数を渡しても渡さなくてもよいという意味
- `if (this.name)` を使うことで、name がある場合とない場合で処理を分けられる

## 今日の重要ポイント

`interface` は「この形を守ってください」というルール。
`class implements interface` は「このクラスはそのルールを守ります」という意味。

ただし、`let user1: Greetable;` のように書くと、`user1` は TypeScript 上では `Greetable` として扱われる。
中身は `new Person()` で作った `Person` オブジェクトでも、使えるプロパティやメソッドは `Greetable` に書かれているものが基準になる。

`new Person()` のように名前を渡さない場合でも、`if (this.name)` で分岐すれば安全に処理できる。
