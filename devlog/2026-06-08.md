# 2026-06-08 学習ログ

## 今日のテーマ

TypeScriptの interface と交差型 `&` の理解

## 今日学んだこと

今日は TypeScript の `interface` と `type`、そして交差型 `&` について学習した。

まず `interface` は、オブジェクトやクラスがどんな形を持つべきかを決める「型のルール」だと理解した。

```
interface Greetable {
  name: string;
  greet(phrase: string): void;
}
```

このように書くことで、`name` を持ち、`greet()` メソッドを持つ型を定義できる。

また、`class Person implements Greetable` と書くことで、`Person` クラスに `Greetable` のルールを守らせることができる。

```
class Person implements Greetable {
  name: string;

  constructor(n: string) {
    this.name = n;
  }

  greet(phrase: string) {
    console.log(phrase + " " + this.name);
  }
}
```

`implements` は、interface の内容を class に強制するためのものだと理解した。

## 交差型 `&` について

次に、`type` を使った交差型を学習した。

```
type Admin = {
  name: string;
  privileges: string[];
};

type Employee = {
  name: string;
  startDate: Date;
};

type ElevatedEmployee = Admin & Employee;
```

この場合、`ElevatedEmployee` は `Admin` と `Employee` の両方を満たす型になる。

つまり、以下の3つがすべて必要になる。

```
name: string;
privileges: string[];
startDate: Date;
```

実際に以下のコードは正しく動く。

```
const e1: ElevatedEmployee = {
  name: "Max",
  privileges: ["create-server"],
  startDate: new Date(),
};
```

ここで `&` は「どちらか」ではなく、「両方必要」という意味だと理解した。

## union型と交差型の組み合わせ

さらに、union型どうしに `&` を使う例も確認した。

```
type Combinable = string | number;
type Numeric = number | boolean;

type Universal = Combinable & Numeric;
```

この場合、`Combinable` は `string | number`、`Numeric` は `number | boolean` なので、両方に共通している型は `number` だけになる。

そのため、`Universal` は実質 `number` 型になる。

```
const value: Universal = 42;
```

これはOK。

しかし、以下はエラーになる。

```
const value1: Universal = "hello";
const value2: Universal = true;
```

`"hello"` は `Combinable` には入るが `Numeric` には入らない。
`true` は `Numeric` には入るが `Combinable` には入らない。

つまり、union型どうしの `&` は「共通部分だけが残る」と理解した。

## 今日の重要ポイント

今日の一番大事なポイントは、`&` の意味が状況によって見え方が変わること。

オブジェクト型どうしの場合は、プロパティが合体する。

```
type ElevatedEmployee = Admin & Employee;
```

この場合は、`Admin` と `Employee` の両方のプロパティが必要になる。

一方で、union型どうしの場合は、共通している型だけが残る。

```
type Universal = Combinable & Numeric;
```

この場合は、`string | number` と `number | boolean` の共通部分である `number` だけが残る。

## 今日の理解

`interface` は、class や object の形を決めるルール。
`implements` は、そのルールを class に守らせるもの。
`type` でもオブジェクト型を作れる。
`&` は「両方を満たす型」を作る。
オブジェクト型ではプロパティが合体し、union型では共通部分だけが残る。

## まだ少し難しいところ

`&` がオブジェクト型では「合体」に見えるのに、union型では「共通部分」に見えるところが少しややこしい。

ただし、どちらも本質は同じで、「両方を満たすもの」と考えれば整理しやすい。

## 今日のまとめ

今日は TypeScript の `interface` と交差型 `&` について学習した。

`interface` は「型のルール」、`implements` は「class にルールを守らせる」、`&` は「両方を満たす型」という考え方で整理できた。

特に、`Admin & Employee` のようなオブジェクト型ではプロパティが合体し、`(string | number) & (number | boolean)` のような union型では共通部分だけが残ることを理解した。
