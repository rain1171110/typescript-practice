# 2026-06-09 学習ログ

## 今日のテーマ

TypeScriptのUnion型と型ガードについて学習した。

Union型では、変数や引数が複数の型のどれかになる可能性がある。
そのため、共通しているプロパティやメソッドはそのまま使えるが、片方の型にしかないものは、そのまま使うことができない。

そこで、`typeof`、`in`、`instanceof`、`switch` を使って型を確認してから処理する方法を学んだ。

---

## 1. typeof を使った型ガード

```
type Combinable = string | number;

function add(a: Combinable, b: Combinable) {
  if (typeof a === "string" || typeof b === "string") {
    return a.toString() + b.toString();
  }
  return a + b;
}

console.log(add(2, 5));
console.log(add("2", 5));
```

### 学んだこと

`Combinable` は `string | number` なので、`a` と `b` は文字列か数値のどちらかになる。

そのまま `a + b` をすると、文字列結合なのか数値計算なのかが曖昧になる。
そのため、`typeof` を使って `string` かどうかを判定した。

```
if (typeof a === "string" || typeof b === "string")
```

この条件に当てはまる場合は、文字列として結合する。

```
return a.toString() + b.toString();
```

どちらも number の場合は、普通に足し算をする。

```
return a + b;
```

## 2. in を使った型ガード

```
type Admin = {
  name: string;
  privileges: string[];
};

type Employee = {
  name: string;
  startDate: Date;
};

type ElevatedEmployee = Admin & Employee;

const e1: ElevatedEmployee = {
  name: "Max",
  privileges: ["create-server"],
  startDate: new Date(),
};

type UnknownEmployee = Employee | Admin;

function printEmployeeInformation(emp: UnknownEmployee) {
  console.log(emp.name);

  if ("privileges" in emp) {
    console.log("Privileges: " + emp.privileges);
  }

  if ("startDate" in emp) {
    console.log("Start Date: " + emp.startDate);
  }
}

printEmployeeInformation(e1);
```

### 学んだこと

`Admin & Employee` は、Admin と Employee の両方の情報を持つ型。

```
type ElevatedEmployee = Admin & Employee;
```

つまり、`name`、`privileges`、`startDate` をすべて持っている。

一方で、

```
type UnknownEmployee = Employee | Admin;
```

は、Employee か Admin のどちらかという意味。

そのため、共通している `name` はそのまま使える。

```
console.log(emp.name);
```

しかし、`privileges` は Admin にしかない。
`startDate` は Employee にしかない。

だから、`in` を使って、そのプロパティがあるかどうかを確認する。

```
if ("privileges" in emp) {
  console.log(emp.privileges);
}
```

この中では、TypeScriptが `emp` を Admin と判断してくれる。

## 3. class と in を使った型ガード

```
class Car {
  drive() {
    console.log("運転中...");
  }
}

class Truck {
  drive() {
    console.log("トラックを運転中...");
  }

  loadCargo(amount: number) {
    console.log("荷物を載せています..." + amount);
  }
}

type Vehicle = Car | Truck;

const v1 = new Car();
const v2 = new Truck();

function useVehicle(vehicle: Vehicle) {
  vehicle.drive();

  if ("loadCargo" in vehicle) {
    vehicle.loadCargo(1000);
  }
}

useVehicle(v1);
useVehicle(v2);
```

### 学んだこと

`Vehicle` は `Car | Truck` なので、Car か Truck のどちらか。

```
type Vehicle = Car | Truck;
```

`Car` と `Truck` の両方に `drive()` があるので、これはそのまま使える。

```
vehicle.drive();
```

しかし、`loadCargo()` は Truck にしかない。
そのため、`in` を使って確認する。

```
if ("loadCargo" in vehicle) {
  vehicle.loadCargo(1000);
}
```

この中では、TypeScriptが `vehicle` を Truck と判断してくれる。

## 4. instanceof を使った型ガード

```
class Car {
  drive() {
    console.log("運転中...");
  }
}

class Truck {
  drive() {
    console.log("トラックを運転中...");
  }

  loadCargo(amount: number) {
    console.log("荷物を載せています..." + amount);
  }
}

type Vehicle = Car | Truck;

const v1 = new Car();
const v2 = new Truck();

function useVehicle(vehicle: Vehicle) {
  vehicle.drive();

  if (vehicle instanceof Truck) {
    vehicle.loadCargo(1000);
  }
}

useVehicle(v1);
useVehicle(v2);
```

### 学んだこと

`instanceof` は、あるオブジェクトが特定の class から作られたものかどうかを判定する。

```
if (vehicle instanceof Truck)
```

これは、`vehicle` が Truck クラスから作られたインスタンスなら true になる。

そのため、この中では `vehicle` は Truck と判断される。

```
vehicle.loadCargo(1000);
```

`class` を使っている場合は、`instanceof` が使える。
一方で、`type` や `interface` は JavaScriptの実行時には存在しないので、`instanceof` では判定できない。

## 5. switch を使った判別可能な Union型

```
interface Bird {
  type: "bird";
  flyingSpeed: number;
}

interface Horse {
  type: "horse";
  runningSpeed: number;
}

type Animal = Bird | Horse;

function moveAnimal(animal: Animal) {
  let speed;

  switch (animal.type) {
    case "bird":
      speed = animal.flyingSpeed;
      break;

    case "horse":
      speed = animal.runningSpeed;
      break;
  }

  console.log("移動速度:" + speed);
}

moveAnimal({ type: "bird", flyingSpeed: 10 });
```

### 学んだこと

`Bird` と `Horse` には、共通の目印として `type` がある。

```
type: "bird";
type: "horse";
```

この `type` を使うことで、Animal が Bird なのか Horse なのかを判定できる。

```
switch (animal.type)
```

`case "bird"` の中では、TypeScriptが `animal` を Bird と判断する。

```
speed = animal.flyingSpeed;
```

`case "horse"` の中では、TypeScriptが `animal` を Horse と判断する。

```
speed = animal.runningSpeed;
```

このように、共通の判定用プロパティを持たせた Union型を、判別可能なUnion型という。

## 今日のまとめ

今日は、Union型を安全に扱うための型ガードについて学習した。

Union型では、共通しているプロパティやメソッドはそのまま使える。
しかし、片方の型にしかないプロパティやメソッドは、そのまま使うことができない。

そのため、次のような型ガードを使う。

```
typeof
```

文字列や数値など、基本的な型を判定するときに使う。

```
in
```

特定のプロパティが存在するかを確認するときに使う。

```
instanceof
```

class から作られたインスタンスかどうかを確認するときに使う。

```
switch
```

`type: "bird"` のような共通の目印プロパティを使って、どの型なのかを判定するときに使う。

今日の学習で、Union型は「どちらか分からない型」なので、使う前に確認する必要があると理解した。
特に、`type` のような目印を持たせておくと、後から処理を分けやすくなると分かった。

## 感想

今日は、Union型と型ガードの関係を学習した。

最初は、`|` を使うと複数の型を扱えるだけだと思っていた。
しかし、実際には「どちらの型か分からない状態」になるため、共通していないプロパティはそのまま使えないことが分かった。

`typeof`、`in`、`instanceof`、`switch` はそれぞれ使う場面が違う。
特に、class の場合は `instanceof`、interface や type の場合は `in` や `type` プロパティを使うという違いが少し整理できた。

Union型を使うときは、まず「共通しているものは何か」「片方にしかないものは何か」を考えることが大事だと感じた。
