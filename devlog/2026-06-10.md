TypeScriptのDOM操作とインデックスシグネチャを理解する

## 今日学んだこと

今日は、TypeScriptでHTML要素を扱うときの型指定と、オブジェクトのプロパティ名を柔軟に扱うインデックスシグネチャについて学習した。

まず、`document.getElementById()` を使ってHTML要素を取得する場合、TypeScriptでは戻り値が `HTMLElement | null` になることを確認した。
そのため、取得した要素が本当に存在するかどうかを `if` 文で確認する必要がある。

```ts
const userInputElement = document.getElementById("user-input");

if (userInputElement) {
  (userInputElement as HTMLInputElement).value = "こんにちは";
}

console.log(userInputElement);
```

このコードでは、`if (userInputElement)` によって `null` ではないことを確認している。
ただし、TypeScriptから見ると、この時点ではまだただの `HTMLElement` として扱われるため、`.value` を使うには `as HTMLInputElement` で「これはinput要素です」と教える必要がある。

また、前に学習した以下の書き方との違いも整理した。

```ts
const userInputElement = document.getElementById(
  "user-input",
)! as HTMLInputElement;

userInputElement.value = "こんにちは";

console.log(userInputElement);
```

`!` は「この要素は必ず存在する」とTypeScriptに伝える書き方。
一方で、`if` 文を使う方法は、実際に存在するか確認してから処理するため、より安全な書き方だと理解した。

## Reactとの違い

Reactを使う場合は、基本的に `document.getElementById()` でDOMを直接取得する場面は少ない。
Reactでは、inputの値は `useState` で管理することが多い。

```tsx
const [inputValue, setInputValue] = useState("");

return (
   setInputValue(event.target.value)}
  />
);
```

普通のTypeScriptではDOMを直接触るため、`as HTMLInputElement` のような型キャストが必要になりやすい。
しかしReactでは、基本的にstateで画面を管理するため、毎回 `getElementById()` や型キャストを書く必要は少ない。
ただし、inputにフォーカスを当てたい場合など、DOMを直接触る必要があるときは `useRef(null)` を使う。

## インデックスシグネチャ

次に、インデックスシグネチャについて学習した。

```ts
interface ErrorContainer {
  [prop: string]: string;
}

const errorBag: ErrorContainer = {
  email: "正しいメールアドレスではありません",
  username: "ユーザ名に記号を含めることはできません。",
};

console.log(errorBag);
```

`[prop: string]: string;` は、プロパティ名は文字列で、値も文字列にするという意味。

つまり、`email` や `username` のように、事前にプロパティ名が決まっていなくても、文字列のプロパティ名であれば自由に追加できる。
ただし、その値は必ず `string` にする必要がある。

```ts
interface ErrorContainer {
  [prop: string]: string;
}
```

この形は、フォームのエラーメッセージをまとめるような場面で使いやすい。

## numberやbooleanの場合

`[prop: string]: string;` の右側は、入れたい値の型に合わせて変更できる。

```ts
interface ScoreContainer {
  [prop: string]: number;
}

const scoreBag: ScoreContainer = {
  math: 80,
  english: 90,
};
```

この場合は、プロパティ名は文字列で、値は数字になる。

```ts
interface CheckContainer {
  [prop: string]: boolean;
}

const checkBag: CheckContainer = {
  email: true,
  username: false,
};
```

この場合は、プロパティ名は文字列で、値はbooleanになる。

つまり、

```ts
[prop: string]: string;
[prop: string]: number;
[prop: string]: boolean;
```

のように、右側は「そのプロパティに入れたい値の型」を指定する。

## 今日の理解

今日のポイントは、型を2つに分けて考えること。

```ts
[prop: string]: string;
```

左側の `string` は、プロパティ名の型。
右側の `string` は、値の型。

つまり、

```txt
[プロパティ名の型]: 値の型;
```

という形で考えると理解しやすい。

## 今日のまとめ

今日は、TypeScriptでDOM要素を扱うときに、なぜ `as HTMLInputElement` が必要になるのかを学んだ。
また、ReactではDOMを直接操作するよりも、stateで画面を管理するため、通常のDOM操作とは考え方が違うことも理解できた。

さらに、インデックスシグネチャでは、プロパティ名を自由に増やせる代わりに、値の型を決めておく必要があると分かった。

今日の理解としては、

- `if (userInputElement)` は null チェック
- `as HTMLInputElement` は input要素として扱うための型指定
- Reactでは基本的にDOMを直接触らず、stateで管理する
- `[prop: string]: string;` は、文字列のプロパティ名に文字列の値を入れるという意味
- 右側の型を変えれば、numberやbooleanの値も扱える

という内容を整理できた。
