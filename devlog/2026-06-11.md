# 2026-06-11 学習ログ

## 今日のテーマ

TypeScriptの安全な型判定：型ガード・オーバーロード・null対策の理解

## 今日学んだこと

今日は、TypeScriptで値の型を安全に扱う方法について学習した。

まず、関数オーバーロードについて学んだ。
`add` 関数では、引数が `number` 同士なら戻り値は `number`、`string` が含まれる場合は戻り値が `string` になる。
このように、引数の組み合わせによって戻り値の型が変わる場合、オーバーロードを書くことで TypeScript に正確な戻り値の型を伝えられると理解した。

```ts
type Combinable = string | number;

function add(a: number, b: number): number;
function add(a: string, b: string): string;
function add(a: string, b: number): string;
function add(a: number, b: string): string;

function add(a: Combinable, b: Combinable) {
  if (typeof a === "string" || typeof b === "string") {
    return a.toString() + b.toString();
  }
  return a + b;
}

const result = add("Hello", "TypeScript");
result.split(" ");

console.log(result);
console.log(add(2, 5));
```

オーバーロードのメリットは、戻り値が `string | number` のように曖昧にならず、`string` のときは `split()`、`number` のときは `toFixed()` など、その型専用のメソッドを安全に使えることだと分かった。

次に、オプショナルチェーン `?.` について学んだ。
オブジェクトの中にプロパティが存在するか分からない場合に、エラーを防ぎながら安全に値を取得できる。

```ts
const fetchedUserData = {
  id: "u1",
  name: "user1",
  job: {
    title: "Developer",
    description: "TypeScript",
  },
};

console.log(fetchedUserData?.job?.title);
```

`?.` は、「あれば取りに行く。なければ `undefined` で止まる」という意味だと理解した。

次に、Null合体演算子 `??` について学んだ。
左側の値が `null` または `undefined` の場合だけ、右側の値を使う。

```ts
const userInput = null;

const storedData = userInput ?? "DEFAULT";

console.log(storedData);
```

`||` との違いも重要で、`||` は空文字 `""` や `0` も false と判断するが、`??` は `null` と `undefined` のときだけ初期値を使う。

最後に、型ガードについて学んだ。
型ガードとは、実行時に値の型を確認して、その型専用のプロパティやメソッドを安全に使えるようにする仕組みである。

代表的な型ガードには、以下のようなものがある。

```ts
typeof
in
instanceof
switch + type プロパティ
```

`typeof` は `string` や `number` の判定に使う。
`in` はオブジェクトに特定のプロパティがあるか確認するときに使う。
`instanceof` はクラスから作られたインスタンスか確認するときに使う。
`switch + type` は、判別可能な Union 型で使う。

特に、判別可能な Union 型は、オブジェクトの種類を安全に分けるときに便利だと分かった。

```ts
interface Bird {
  type: "bird";
  flyingSpeed: number;
}

interface Horse {
  type: "horse";
  runningSpeed: number;
}

type Animal = Bird | Horse;

function moveAnimal(animal: Animal) {
  let speed;

  switch (animal.type) {
    case "bird":
      speed = animal.flyingSpeed;
      break;
    case "horse":
      speed = animal.runningSpeed;
      break;
  }

  console.log("移動速度:" + speed);
}
```

また、型キャストについても学んだ。
型キャストは、TypeScriptには分からないけど、自分には型が分かっているときに使う。
ただし、型キャストは実行時に安全確認をしてくれるものではないため、必要に応じて型ガードと組み合わせることが大事だと分かった。

```ts
const input = document.getElementById("user-input") as HTMLInputElement;

input.value = "Hello";
```

より安全に書くなら、以下のように `instanceof` を使う。

```ts
const input = document.getElementById("user-input");

if (input instanceof HTMLInputElement) {
  input.value = "Hello";
}
```

## 今日の理解

型ガードは、値がどの型なのかを確認してから、その型専用の処理を行うためのものだと理解した。
型キャストは TypeScript に「この型として扱って」と伝えるものだが、実際に安全確認しているわけではない。
そのため、実行時エラーを防ぎたい場合は、型キャストだけでなく型ガードを使うことが大切だと分かった。
