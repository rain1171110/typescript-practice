## 今日学習したこと

今日は、TypeScriptで複数の型を安全に扱う方法について復習した。

まず、`Bird` と `Horse` を使って、判別可能な Union 型を確認した。
`type: "鳥"` や `type: "馬"` のように共通のプロパティを用意しておくことで、`switch` 文の中で TypeScript が自動的に型を判断してくれることを復習した。

```ts
interface Bird {
  type: "鳥";
  flyingSpeed: number;
}

interface Horse {
  type: "馬";
  runningSpeed: number;
}

type Animal = Bird | Horse;

function moveAnimal(animal: Animal) {
  let speed: number;

  switch (animal.type) {
    case "鳥":
      speed = animal.flyingSpeed;
      break;
    case "馬":
      speed = animal.runningSpeed;
      break;
  }

  console.log(`${animal.type}の移動速度:` + speed);
}
```

Union型は、そのままだと共通しているプロパティしか安全に使えない。
しかし、`type` のような判別用プロパティを使うことで、`Bird` なのか `Horse` なのかを安全に分けられることが分かった。

次に、DOM要素に対する型キャストを復習した。

```ts
const userInputElement = document.getElementById("user-input");

if (userInputElement) {
  (userInputElement as HTMLInputElement).value = "こんにちは";
}
```

`getElementById()` の戻り値は `HTMLElement | null` になるため、そのままでは `.value` を使えない。
そこで `as HTMLInputElement` を使い、TypeScriptに「これはinput要素として扱う」と伝える必要があることを確認した。

また、インデックスシグネチャについても復習した。

```ts
interface ErrorContainer {
  [prop: string]: string;
}

const errorBag: ErrorContainer = {
  email: "正しいメールアドレスではありません",
  username: "ユーザ名に記号を含めることはできません。",
};
```

`[prop: string]: string` は、プロパティ名は自由だが、値は必ず `string` にするという意味。
エラーメッセージのように、あとからどんなキーが増えるか分からないオブジェクトに使える。

さらに、Intersection型と関数オーバーロードも復習した。

```ts
type Combinable = string | number;
type Numeric = number | boolean;

type Universal = Combinable & Numeric;

const value: Universal = 42;
```

`|` は「どれか1つでOK」、`&` は「両方の条件を満たす」という意味。
`Combinable` と `Numeric` の共通部分は `number` なので、`Universal` は `number` になる。

関数オーバーロードでは、引数の型によって戻り値の型が変わる関数を復習した。

```ts
function add(a: number, b: number): number;
function add(a: string, b: string): string;
function add(a: string, b: number): string;
function add(a: number, b: string): string;

function add(a: string | number, b: string | number) {
  if (typeof a === "string" || typeof b === "string") {
    return a.toString() + b.toString();
  }
  return a + b;
}
```

オーバーロードを書くことで、`add("Hello ", "TypeScript")` の戻り値が `string` だと TypeScript が判断できる。
そのため、`result.split(" ")` のような string のメソッドを安全に使えることを確認した。

最後に、ジェネリクスを復習した。

```ts
const names: Array = [];
```

`Array` は `string[]` と同じで、stringだけを入れられる配列を表す。

```ts
const promise = new Promise((resolve, reject) => {
  setTimeout(() => {
    resolve("終わりました");
  }, 2000);
});
```

`Promise` は、最終的に `string` を返す Promise という意味。
そのため、`then` の中の `data` は `string` として扱われ、`data.split(" ")` を使える。

また、ジェネリクスの制約も復習した。

```ts
function merge(objA: T, objB: U) {
  return Object.assign(objA, objB);
}

const mergedObj = merge({ name: "Max", hobbies: ["Sports"] }, { age: 30 });
```

`T` や `U` は、呼び出したときの引数から自動で決まる型。
`extends object` を付けることで、引数をオブジェクトに限定できる。
これにより、`Object.assign()` で安全にオブジェクト同士を結合できる。

## 今日の気づき

TypeScriptでは、ただ型を書くのではなく、「TypeScriptにどう判断してもらうか」が大事だと感じた。

Union型では `type` プロパティを使って型を分ける。
DOM操作では `as HTMLInputElement` を使って具体的な型を伝える。
関数オーバーロードでは、引数と戻り値の関係をTypeScriptに教える。
ジェネリクスでは、使うときに型を決めつつ、必要なら `extends` で制限をかける。

少しずつ、TypeScriptがなぜ安全にコードを書けるのかが分かってきた。
