TypeScript デコレーターの流れと getter / setter・static・prototype の整理

今日は TypeScript のデコレーターを中心に復習した。
最初は `WithTemplate` の中で出てくる `constructor` や `new constructor()` の意味が分かりにくかったが、最終的に「デコレーターが付いた `Person` クラスそのものが `constructor` に渡されている」と理解できた。

## 学習した内容

### 1. クラスデコレーターの基本

```ts
function Logger(logString: string) {
  console.log("LOGGER ファクトリ");
  return function (constructor: Function) {
    console.log(logString);
    console.log(constructor);
  };
}
```

`@Logger("ログ出力中")` と書くと、まず `Logger("ログ出力中")` が実行される。
その戻り値として、内側の関数が返される。

```ts
return function (constructor: Function) {
  console.log(logString);
  console.log(constructor);
};
```

この `constructor` には、デコレーターが付いたクラスそのものが入る。

```ts
@Logger("ログ出力中")
class Person {}
```

この場合のイメージ:

```ts
Logger("ログ出力中")(Person);
```

---

### 2. `new constructor()` の意味

```ts
const p = new constructor();
```

ここでの `constructor` は `Person` クラスそのものなので、頭の中では次のように考えられる。

```ts
const p = new Person();
```

ただし、`new Person()` しただけではオブジェクト自体はコンソールに表示されない。
表示されるのは、`constructor` の中に `console.log()` があるから。

```ts
class Person {
  name = "Max";

  constructor() {
    console.log("Personオブジェクト作成中...");
  }
}
```

そのため、以下のように `new` が2回あると、

```ts
const p = new constructor();
const pers = new Person();
```

`Personオブジェクト作成中...` は2回表示される。
しかし、オブジェクト自体を表示しているのは `console.log(pers);` だけなので、コンソールに出るオブジェクト表示は1つだけになる。

### 3. `WithTemplate` の流れ

```ts
function WithTemplate(template: string, hookId: string) {
  console.log("TEMPLATE ファクトリ");
  return function (constructor: any) {
    console.log("テンプレートを表示");

    const hookEl = document.getElementById(hookId);
    const p = new constructor();

    if (hookEl) {
      hookEl.innerHTML = template;
      hookEl.querySelector("h1")!.textContent = p.name;
    }
  };
}
```

このデコレーターは、クラスを受け取ってインスタンスを作り、その `name` を HTML に表示する処理をしている。

```ts
@WithTemplate("Personオブジェクト", "app")
class Person {
  name = "Max";
}
```

流れ:

```ts
WithTemplate("Personオブジェクト", "app");
WithTemplate("Personオブジェクト", "app")(Person);
```

対応関係:

```ts
template = "Personオブジェクト";
hookId = "app";
constructor = Person;
```

### 4. 複数デコレーターの実行順序

```ts
@Logger("ログ出力中")
@WithTemplate("Personオブジェクト", "app")
class Person {}
```

デコレーターが複数ある場合、順番が少し特殊。

ファクトリ関数は上から実行される。

```txt
LOGGER ファクトリ
TEMPLATE ファクトリ
```

返されたデコレーター関数本体は下から実行される。

```txt
テンプレートを表示
ログ出力中
```

覚え方:

```txt
ファクトリは上から
デコレーター本体は下から
```

### 5. getter / setter と `_price`

```ts
class Product {
  title: string;
  private _price: number;

  set price(val: number) {
    if (val > 0) {
      this._price = val;
    } else {
      throw new Error("不正な価格です: 0以下は設定できません");
    }
  }

  constructor(t: string, p: number) {
    this.title = t;
    this._price = p;
  }

  getPriceWithTax(tax: number) {
    return this._price * (1 + tax);
  }
}
```

`_price` の `_` は TypeScript の特別な文法ではなく、「内部用の値」という目印。

```ts
private _price: number;
```

`price` は外から使う入口。

```ts
set price(val: number) {
  this._price = val;
}
```

つまり、

```ts
product.price = 1000;
```

と書くと setter が動き、`val = 1000` になる。

ただし constructor 内で直接こう書くと、

```ts
this._price = p;
```

setter のチェックは通らない。
チェックを通したいなら、

```ts
this.price = p;
```

と書く。

### 6. static プロパティ

`static` は、インスタンスではなくクラスそのものに属するプロパティ。

```ts
class Product {
  static taxRate = 0.1;
}
```

使うときは、

```ts
Product.taxRate;
```

インスタンスからは呼べない。

```ts
const product = new Product("Book", 1000);
// product.taxRate; // エラー
```

理解の要点:

```txt
static は new して作ったインスタンスではなく、
クラス名から直接呼び出す
```

### 7. prototype とは

prototype は、インスタンスたちが共通で使うメソッド置き場。

```ts
class Product {
  title: string;

  constructor(t: string) {
    this.title = t;
  }

  getPriceWithTax(tax: number) {
    return 1000 * (1 + tax);
  }
}
```

`title` はインスタンスごとに持つ。

```ts
const book = new Product("本");
const pen = new Product("ペン");
```

一方、`getPriceWithTax` は各インスタンスにコピーされるのではなく、基本的に `Product.prototype` 側に置かれる。

```txt
Product.prototype
  └─ getPriceWithTax()
```

### 8. 4種類のデコレーター

```ts
class Product {
  @Log
  title: string;

  @Log2
  set price(val: number) {}

  @Log3
  getPriceWithTax(@Log4 tax: number) {}
}
```

#### Property デコレーター

```ts
function Log(target: any, propertyName: string | Symbol) {
  console.log("Property デコレータ");
  console.log(target, propertyName);
}
```

```ts
@Log
title: string;
```

これはプロパティに付くデコレーター。

```ts
Log(Product.prototype, "title");
```

---

#### Accessor デコレーター

```ts
function Log2(target: any, name: string, descriptor: PropertyDescriptor) {
  console.log("Accessor デコレータ");
  console.log(target);
  console.log(name);
  console.log(descriptor);
}
```

```ts
@Log2
set price(val: number) {}
```

これは getter / setter に付くデコレーター。`descriptor` には setter の情報が入る。

---

#### Method デコレーター

```ts
function Log3(
  target: any,
  name: string | Symbol,
  descriptor: PropertyDescriptor,
) {
  console.log("Method デコレータ");
  console.log(target);
  console.log(name);
  console.log(descriptor);
}
```

```ts
@Log3
getPriceWithTax(tax: number) {}
```

これはメソッドに付くデコレーター。

```ts
Log3(Product.prototype, "getPriceWithTax", descriptor);
```

---

#### Parameter デコレーター

```ts
function Log4(target: any, name: string | Symbol, position: number) {
  console.log("Parameter デコレータ");
  console.log(target);
  console.log(name);
  console.log(position);
}
```

```ts
getPriceWithTax(@Log4 tax: number) {}
```

これは引数に付くデコレーター。`position` は引数の位置を表し、最初の引数なら `0`。

## 今日の重要ポイント

```txt
デコレーターは new したときではなく、
クラスが定義されたタイミングで実行される
```

```txt
クラスデコレーターにはクラスそのものが渡される
プロパティデコレーターには prototype とプロパティ名が渡される
メソッド・アクセサデコレーターには descriptor も渡される
パラメーターデコレーターには引数の位置が渡される
```

---

## 今日の理解まとめ

今日は、最初に `new constructor()` の意味でかなり混乱したが、最終的に

```ts
const p = new constructor();
```

は

```ts
const p = new Person();
```

と考えられることを理解できた。

また、`new` すると constructor は動くが、`console.log()` しない限りオブジェクト自体は表示されないことも整理できた。

後半では `Product` クラスを使って、プロパティデコレーター、アクセサデコレーター、メソッドデコレーター、パラメーターデコレーターの違いを確認した。

まだ全部を完全に使いこなす段階ではないが、
「デコレーターはクラスやプロパティ、メソッドに追加情報や追加処理をくっつける仕組み」という全体像はかなり見えてきた。
