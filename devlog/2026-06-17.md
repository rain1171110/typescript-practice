**TypeScript デコレーター：クラスを差し替えるデコレータと、`...args` の正体を理解する**

今日は、TypeScript のデコレーターの中でも少し難しい部分を学習した。
特に、クラスデコレータが **元のクラスを受け取って、新しいクラスを返す** 仕組みを確認した。

## 今日学んだこと

### 1. クラスデコレータはクラスを受け取る

```ts
function WithTemplate(template: string, hookId: string) {
  return function (
    originalConstructor: new (...args: any[]) => { name: string },
  ) {
    return class extends originalConstructor {
      constructor(..._args: any[]) {
        super();
        console.log("テンプレートを表示");
      }
    };
  };
}
```

ここで `originalConstructor` には、元の `Person` クラスが入る。

つまりイメージとしては、

```ts
originalConstructor = Person;
```

となる。

そのため、

```ts
return class extends originalConstructor
```

は、

```ts
return class extends Person
```

のように考えてよい。

---

### 2. 今回の `WithTemplate` はクラスを差し替えている

前の形では、デコレータの中で直接インスタンスを作っていた。

```ts
const p = new constructor();
```

この場合、デコレータ実行時に `Person` オブジェクトが作られる。

しかし今回のコードでは、

```ts
return class extends originalConstructor {
  constructor(..._args: any[]) {
    super();
    console.log("テンプレートを表示");
  }
};
```

としている。

これは、元の `Person` クラスを継承した **新しいクラス** を返している。

つまり、

```ts
const pers = new Person();
```

と書いていても、実際にはデコレータによって拡張されたクラスの constructor が動く。

---

### 3. `super()` は元のクラスの constructor を呼ぶ

```ts
constructor(..._args: any[]) {
  super();
}
```

この `super()` は、親クラスの constructor を呼ぶ。

今回なら、親クラスは `originalConstructor`、つまり元の `Person`。

そのため、

```ts
super();
```

によって、

```ts
constructor() {
  console.log("Personオブジェクト作成中…");
}
```

が実行される。

そして `name = "Max"` も作られるので、その後に

```ts
this.name;
```

を使うことができる。

---

### 4. `new (...args: any[]) => { name: string }` の意味

今日一番大事だったのはここ。

```ts
new (...args: any[]) => { name: string }
```

これは、

**何個でも引数を受け取って new できて、作られるインスタンスが `name: string` を持っているクラス**

という意味。

つまり、

```ts
new ()
```

でも、

```ts
new ("Taro", 30)();
```

でも対応できるようにするための書き方。

---

### 5. `...args` はコピーではない

最初は「何かをコピーしているのか？」と疑問になった。

でも `...args` はコピーではなく、

**渡された引数を全部まとめて受け取る書き方**

だった。

例えば、

```ts
function test(...args: any[]) {
  console.log(args);
}

test("Book", 100);
```

この場合、`args` の中身はこうなる。

```ts
["Book", 100];
```

つまり `...args` は、引数をまとめて配列として受け取るもの。

---

### 6. `super(...args)` にすると親クラスへ引数を渡せる

今回のコードでは、

```ts
constructor(..._args: any[]) {
  super();
}
```

となっていた。

これは、引数は受け取っているけど、親クラスには渡していない。

もし親クラスの constructor に引数がある場合は、次のように書くほうが自然。

```ts
constructor(...args: any[]) {
  super(...args);
}
```

これなら、

```ts
new User("Taro", 30);
```

したときに、

```ts
args = ["Taro", 30];
```

として受け取り、

```ts
super(...args);
```

で親クラスに渡せる。

つまり、

```ts
super("Taro", 30);
```

と同じ意味になる。

## 今日の理解

今日は、デコレーターが単にログを出すだけではなく、**クラスそのものを加工できる** ことを学んだ。

特に重要だったのは、

```ts
return class extends originalConstructor
```

の部分。

これは、元のクラスを継承した新しいクラスを作り、その constructor に追加処理を入れている。

また、

```ts
...args
```

はコピーではなく、**渡された引数を全部まとめて受け取るための書き方** だと理解した。

---

## 今日のまとめ

TypeScript のデコレーターは、関数が自動で呼ばれる仕組み。
クラスデコレーターでは、元のクラスを受け取り、新しいクラスを返すことで、constructor の処理を後から追加できる。

`...args` は、どんな constructor にも対応できるように、引数をまとめて受け取るための書き方。

今日のポイントはこれ。

```ts
new (...args: any[]) => { name: string }
```

これは、

**どんな引数でも new できて、作られるオブジェクトが name を持つクラス**

という意味。
