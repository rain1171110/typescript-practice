## 今日のテーマ

`this` のズレと `Autobind` デコレーターの仕組みを学習した。

## 今日学んだこと

今日は、イベントリスナーにクラスのメソッドを渡すときに起こる `this` のズレについて学習した。

最初に、以下のコードを確認した。

```
class Printer {
  message = "クリックしました";

  showMessage() {
    console.log(this.message);
  }
}

const p = new Printer();

const button = document.querySelector("button")!;
button.addEventListener("click", p.showMessage.bind(p));
```

このコードでは、`p.showMessage.bind(p)` とすることで、`showMessage` の中の `this` を `p` に固定している。

もし `bind(p)` を書かずに、

```
button.addEventListener("click", p.showMessage);
```

とすると、`showMessage` が `p` から切り離されてイベントリスナーに渡されるため、`this` が `p` を指さなくなる。

そのため、`this.message` が正しく取得できない可能性がある。

## Autobind デコレーター

次に、毎回 `.bind(p)` を書かなくてもよいようにする `Autobind` デコレーターを学習した。

```
function Autobind(_: any, _2: string, descriptor: PropertyDescriptor) {
  const originalMethod = descriptor.value;
  const adjDescriptor: PropertyDescriptor = {
    configurable: true,
    enumerable: false,
    get() {
      const boundFn = originalMethod.bind(this);
      return boundFn;
    },
  };
  return adjDescriptor;
}
```

このデコレーターは、元のメソッドを取り出して、getter を使って `this` を自動的に固定した関数を返す。

```
class Printer {
  message = "クリックしました";

  @Autobind
  showMessage() {
    console.log(this.message);
  }
}
```

これにより、以下のように `.bind(p)` を書かなくても動く。

```
const p = new Printer();

const button = document.querySelector("button")!;
button.addEventListener("click", p.showMessage);
```

## getter が動くタイミング

今日一番大事だったのは、なぜ `get()` が動くのかという部分。

```
button.addEventListener("click", p.showMessage);
```

このコードでは、まず第2引数に渡す値として `p.showMessage` を読み取る。

この `p.showMessage` を読んだ瞬間に、`Autobind` デコレーターが返した getter が動く。

```
get() {
  const boundFn = originalMethod.bind(this);
  return boundFn;
}
```

このとき、`p.showMessage` としてアクセスしているので、getter の中の `this` は `p` を指す。

そのため、

```
const boundFn = originalMethod.bind(this);
```

は、実際には次のような意味になる。

```
const boundFn = originalMethod.bind(p);
```

そして、`this` が `p` に固定された関数が `addEventListener` に登録される。

## 今日の理解

`button.addEventListener("click", p.showMessage);` と書いたとき、すぐに `showMessage()` が実行されるわけではない。

まず `p.showMessage` が読み取られる。

その読み取りによって getter が動く。

getter の中で `originalMethod.bind(this)` が実行される。

その結果、`this` が `p` に固定された関数が返る。

その返された関数が、クリックイベントに登録される。

その後、ボタンがクリックされたときに、ブラウザが登録済みの関数を実行する。

## 今日のポイントまとめ

- `p.showMessage()` はメソッドの実行。
- `p.showMessage` はメソッド、または getter から返される値の読み取り。
- getter は、プロパティのように値を読んだ瞬間に動く。
- `@Autobind` は、普通のメソッドを getter 付きのプロパティのように置き換える。
- `get()` の中で `originalMethod.bind(this)` を返すことで、`this` を自動的に固定できる。
- `button.addEventListener("click", p.showMessage);` の中の `p.showMessage` を読んだ時点で getter が動く。
- クリック時に実行するのはブラウザ。
- イベント登録時に getter が動き、クリック時に bind 済み関数が実行される。

## 今日の感想

今日は `this`、`bind`、getter、デコレーターがつながる部分を学習した。

最初は、なぜ `p.showMessage` と書いただけで `get()` が動くのかが分かりにくかった。

しかし、getter はメソッドのように `()` をつけて呼ぶものではなく、プロパティを読むようにアクセスした瞬間に動くものだと理解した。

今回の `Autobind` は、`p.showMessage` を読んだ瞬間に getter を動かし、その中で `this` を `p` に固定した関数を返している。

つまり、見た目は `.bind(p)` を書いていないが、裏側では `originalMethod.bind(p)` と同じことをしている。

デコレーターは魔法のように見えるが、実際には getter と `bind` を組み合わせて、メソッドの `this` を自動で固定している仕組みだと分かった。
