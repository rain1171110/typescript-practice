クラスデコレーターの復習

Logger と WithTemplate を使って、クラスデコレーターの動きを確認した。

function Logger(logString: string) {
console.log("LOGGER ファクトリ");
return function (constructor: Function) {
console.log(logString);
console.log(constructor);
};
}

Logger("ログ出力中") のように書くと、まずファクトリ関数が実行され、その後に実際のデコレーター関数が返される。

@Logger("ログ出力中")
@WithTemplate("<h1>Personオブジェクト</h1>", "app")
class Person {
name = "Max";

constructor() {
console.log("Personオブジェクト作成中…");
}
}

WithTemplate では、元のコンストラクターを継承した新しいクラスを返している。

return class extends originalConstructor {
constructor(...\_args: any[]) {
super();
console.log("テンプレートを表示");

    const hookEl = document.getElementById(hookId);

    if (hookEl) {
      hookEl.innerHTML = template;
      hookEl.querySelector("h1")!.textContent = this.name;
    }

}
};

ここでは super() によって元の Person の constructor が実行され、その後にテンプレート表示の処理が追加される。

各種デコレーターの確認

Product クラスでは、プロパティ・アクセサ・メソッド・パラメーターのデコレーターを確認した。

class Product {
@Log
title: string;

private \_price: number;

@Log2
set price(val: number) {
if (val > 0) {
this.\_price = val;
} else {
throw new Error("不正な価格です- 0以下は設定できません");
}
}

constructor(t: string, p: number) {
this.title = t;
this.\_price = p;
}

@Log3
getPriceWithTax(@Log4 tax: number) {
return this.\_price \* (1 + tax);
}
}

それぞれの役割は以下の通り。

@Log：プロパティデコレーター
@Log2：アクセサデコレーター
@Log3：メソッドデコレーター
@Log4：パラメーターデコレーター

デコレーターは、インスタンス作成時ではなく、クラスが定義されたタイミングで実行される。

Autobind デコレーターの理解

今日は Autobind の理解をかなり深めた。

function Autobind(\_: any, \_2: string, descriptor: PropertyDescriptor) {
const originalMethod = descriptor.value;

const adjDescriptor: PropertyDescriptor = {
configurable: true,
enumerable: false,
get() {
const boundFn = originalMethod.bind(this);
return boundFn;
},
};

return adjDescriptor;
}

@Autobind をつけることで、メソッドを getter 付きのプロパティのように差し替えている。

class Printer {
message = "クリックしました";

@Autobind
showMessage() {
console.log(this.message);
}
}

普通に以下のようにイベントリスナーへ渡すと、this がずれる可能性がある。

button.addEventListener("click", p.showMessage);

本来なら、showMessage の中の this が Printer のインスタンスではなく、クリックされた button 側を参照してしまう。

しかし @Autobind によって、p.showMessage にアクセスした瞬間に getter が動き、元のメソッドに対して bind(this) を行う。

実質的には、以下のように書いたのと同じ状態になる。

button.addEventListener("click", p.showMessage.bind(p));

つまり @Autobind は、イベントリスナーにメソッドを渡しても this がずれないようにする仕組みだと理解した。

フォーム入力と Course クラス

フォームから入力された値を取得し、Course クラスのインスタンスを作る流れも確認した。

class Course {
title: string;
price: number;

constructor(t: string, p: number) {
this.title = t;
this.price = p;
}
}

title と price は、Course オブジェクトが持つプロパティ。

constructor(t: string, p: number) {
this.title = t;
this.price = p;
}

この constructor は、new Course(title, price) で受け取った値を、作成中のオブジェクトに保存する役割を持つ。

フォーム送信時の処理

フォーム送信時には、入力された値を取得して Course オブジェクトを作成する。

const courseForm = document.querySelector("form")!;

courseForm.addEventListener("submit", (event) => {
event.preventDefault();

const titleEl = document.getElementById("title") as HTMLInputElement;
const priceEl = document.getElementById("price") as HTMLInputElement;

const title = titleEl.value;
const price = +priceEl.value;

const createdCourse = new Course(title, price);

if (!validate(createdCourse)) {
alert("正しく入力して下さい！");
return;
}

console.log(createdCourse);
});

priceEl.value は文字列なので、+priceEl.value によって number 型に変換している。

const price = +priceEl.value;

これは以下とほぼ同じ意味。

const price = Number(priceEl.value);
簡易バリデーションの実装

最後に、デコレーターを使った簡易バリデーションの仕組みを学習した。

interface validatorConfig {
[prop: string]: {
[validatebleProp: string]: string[];
};
}

const registeredValidators: validatorConfig = {};

registeredValidators は、どのクラスのどのプロパティに、どんなバリデーションをかけるかを保存する場所。

function Required(target: any, propName: string) {
registeredValidators[target.constructor.name] = {
[propName]: ["required"],
};
}

function PositiveNumber(target: any, propName: string) {
registeredValidators[target.constructor.name] = {
[propName]: ["positive"],
};
}

@Required は必須入力、@PositiveNumber は正の数を意味するバリデーションとして使う。

class Course {
@Required
title: string;

@PositiveNumber
price: number;

constructor(t: string, p: number) {
this.title = t;
this.price = p;
}
}

フォームから作成した Course オブジェクトを validate(createdCourse) に渡し、正しく入力されているかを判定する。

if (!validate(createdCourse)) {
alert("正しく入力して下さい！");
return;
}
今日の理解ポイント

今日の一番大きな理解は、デコレーターは クラスやメソッドの動きをあとから補助・変更する仕組み だということ。

特に Autobind では、普通のメソッドを getter 付きのプロパティのように差し替えることで、p.showMessage にアクセスした瞬間に bind 済み関数を返していることがわかった。

また、フォーム入力から Course インスタンスを作り、デコレーターで登録したルールを使ってバリデーションする流れも確認できた。

まだ曖昧なところ
registeredValidators[target.constructor.name] に、どのようにバリデーション情報が保存されているか
複数のバリデーションがある場合に、前の設定が上書きされないようにする書き方
validate 関数の中で、for...in を使って各プロパティをチェックする処理
デコレーターが「いつ実行されるのか」と、インスタンス作成時の処理との違い
次回やること

次回は、途中まで書いた validate 関数を完成させる。

function validate(obj: object) {
const objValidatorConfig = registeredValidators[obj.constructor.name];

if (!objValidatorConfig) {
return true;
}

let isValid = true;

for (const prop in objValidatorConfig) {
for (const validator of objValidatorConfig[prop]) {
switch (validator) {
case "required":
isValid = isValid && !!obj[prop];
break;
case "positive":
isValid = isValid && obj[prop] > 0;
break;
}
}
}

return isValid;
}

次回は、required と positive のチェックがどのように動いているかを、自分の言葉で説明できるようにする。
