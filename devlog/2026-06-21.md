# 2026-06-21 学習ログ

## テーマ

**TypeScript デコレーターを使ったバリデーション処理の流れを理解する**

今日は、`@Required` と `@PositiveNumber` を使って、フォーム入力値をバリデーションするコードを学習した。

最初は、バリデーションが反映されず、空欄のまま送信しても次のようなオブジェクトが `console.log` に表示されていた。

```ts
Course { title: "", price: 0 }
```

原因は、デコレーターで登録したバリデーション設定が上書きされていたことと、`validate()` の中で `return` を使ってしまい、最初のチェックだけで処理が終わっていたことだった。

---

## 学習した内容

## 1. デコレーターは直接バリデーションしているわけではない

```ts
@Required
title: string;

@PositiveNumber
price: number;
```

このコードは、入力値をその場でチェックしているのではなく、`registeredValidators` に「どのプロパティにどんなルールが必要か」を登録している。

つまり、デコレーターの役割は **チェック係ではなく、ルール登録係**。

---

## 2. registeredValidators はルール表

最終的に、`registeredValidators` の中身はこのような形になる。

```ts
{
  Course: {
    title: ["required"],
    price: ["positive"]
  }
}
```

これは、次の意味になる。

```txt
Course クラスの title は required
Course クラスの price は positive
```

つまり、`registeredValidators` は「どのクラスの、どのプロパティに、どんなチェックをするか」を保存している表。

---

## 3. 上書きしない登録方法

最初は、デコレーターで登録するときに前の設定が消えてしまっていた。

修正後は、スプレッド構文を使って既存の設定を残したまま追加するようにした。

```ts
function Required(target: any, propName: string) {
  registeredValidators[target.constructor.name] = {
    ...registeredValidators[target.constructor.name],
    [propName]: [
      ...(registeredValidators[target.constructor.name]?.[propName] ?? []),
      "required",
    ],
  };
}
```

この書き方により、`title` と `price` の両方のルールを保持できるようになった。

ポイントはここ。

```ts
...registeredValidators[target.constructor.name]
```

これは、すでに登録されているクラスのバリデーション設定を展開して残す。

そしてここ。

```ts
...(registeredValidators[target.constructor.name]?.[propName] ?? [])
```

これは、すでにそのプロパティに登録されているルールがあれば残し、なければ空配列 `[]` を使う。

---

## 4. validate関数の役割

`validate()` は、登録されたルール表を見ながら、実際に作成されたオブジェクトの値をチェックする関数。

```ts
const createdCourse = new Course(title, price);

if (!validate(createdCourse)) {
  alert("正しく入力して下さい！");
  return;
}
```

ここで `createdCourse` の中身と、`registeredValidators` に登録されたルールを照合している。

---

## 5. returnではなくisValidに結果をためる

最初は、`validate()` の中でこう書いていた。

```ts
return !!obj[prop];
```

しかしこれだと、1つ目のチェックで `validate()` が終了してしまう。

修正後は、`isValid` に結果をためる形にした。

```ts
let isValid = true;

isValid = isValid && !!obj[prop];
isValid = isValid && obj[prop] > 0;
```

これにより、`title` と `price` の両方を最後までチェックできるようになった。

## 今日の完成コード

```ts
interface validatorConfig {
  [prop: string]: {
    [validatableProp: string]: string[]; // ["required","positive"]
  };
}

const registeredValidators: validatorConfig = {};

function Required(target: any, propName: string) {
  registeredValidators[target.constructor.name] = {
    ...registeredValidators[target.constructor.name],
    [propName]: [
      ...(registeredValidators[target.constructor.name]?.[propName] ?? []),
      "required",
    ],
  };
}

function PositiveNumber(target: any, propName: string) {
  registeredValidators[target.constructor.name] = {
    ...registeredValidators[target.constructor.name],
    [propName]: [
      ...(registeredValidators[target.constructor.name]?.[propName] ?? []),
      "positive",
    ],
  };
}

function validate(obj: any) {
  const objValidatorConfig = registeredValidators[obj.constructor.name];

  if (!objValidatorConfig) {
    return true;
  }

  let isValid = true;

  for (const prop in objValidatorConfig) {
    const validators = objValidatorConfig[prop];

    if (!validators) {
      continue;
    }

    for (const validator of validators) {
      switch (validator) {
        case "required":
          isValid = isValid && !!obj[prop];
          break;
        case "positive":
          isValid = isValid && obj[prop] > 0;
          break;
      }
    }
  }

  return isValid;
}

class Course {
  @Required
  title: string;

  @PositiveNumber
  price: number;

  constructor(t: string, p: number) {
    this.title = t;
    this.price = p;
  }
}

const courseForm = document.querySelector("form")!;

courseForm.addEventListener("submit", (event) => {
  event.preventDefault();

  const titleEl = document.getElementById("title") as HTMLInputElement;
  const priceEl = document.getElementById("price") as HTMLInputElement;

  const title = titleEl.value;
  const price = +priceEl.value;

  const createdCourse = new Course(title, price);

  if (!validate(createdCourse)) {
    alert("正しく入力して下さい！");
    return;
  }

  console.log(createdCourse);
});
```

## 今日の理解

今日のコードは、次の流れで動いている。

```txt
1. @Required / @PositiveNumber が実行される
2. registeredValidators にバリデーションルールが登録される
3. フォーム送信時に Course オブジェクトが作られる
4. validate(createdCourse) が実行される
5. 登録されたルールと実際の値を照合する
6. ダメなら alert を出して return で止める
```

特に大事なのは、次の整理。

```txt
デコレーター = ルールを登録する
validate = 実際にチェックする
createdCourse = チェックされる対象
```

デコレーターは、バリデーションを直接実行するものではない。  
あとで `validate()` が使うためのルールを登録している。
