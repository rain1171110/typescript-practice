# 今日の学習ログ

## テーマ

**TypeScript デコレーターによるバリデーション処理の理解：`target.constructor.name` と `Course.prototype`**

---

## 今日やったこと

今日は、TypeScript のプロパティデコレーターを使ったバリデーションコードを読み進めた。

扱ったコードでは、`@Required` や `@PositiveNumber` を `Course` クラスのプロパティに付けることで、どのプロパティにどのチェックを行うかを `registeredValidators` に登録していた。

```ts
class Course {
  @Required
  title: string;

  @PositiveNumber
  price: number;
}
```

このコードによって、最終的に裏側では次のような形のデータが作られることを確認した。

```ts
registeredValidators = {
  Course: {
    title: ["required"],
    price: ["positive"],
  },
};
```

---

## 理解したこと

`for...in` は、オブジェクトのキーを1つずつ取り出す構文だと理解した。

```ts
for (const prop in objValidatorConfig) {
  const validators = objValidatorConfig[prop];
}
```

今回の `objValidatorConfig` は次のような形。

```ts
{
  title: ["required"],
  price: ["positive"]
}
```

そのため、`prop` には順番に次の値が入る。

```ts
"title"
"price"
```

つまり、`for...in` は `Course` のチェック対象になっているプロパティ名を取り出している。

---

## 今日の重要ポイント

特に重点的に確認したのは、次のコード。

```ts
target.constructor.name
```

最初は、なぜこれが `"Course"` になるのかがわからなかった。

プロパティデコレーターでは、`target` には `Course` クラスそのものではなく、`Course.prototype` が入る。

```ts
target = Course.prototype;
```

そして、JavaScript では次の関係がある。

```ts
Course.prototype.constructor === Course;
```

そのため、

```ts
target.constructor.name
```

は、実質的に次と同じになる。

```ts
Course.prototype.constructor.name
```

結果として、

```ts
"Course"
```

になる。

---

## 実験コード

理解のために、次のコードを確認した。

```ts
console.log(Course.prototype.constructor);
console.log(Course.prototype.constructor.name);
```

イメージとして、結果はこうなる。

```txt
class Course { ... }
Course
```

この実験によって、`target.constructor.name` が `"Course"` になる理由が少しつながった。

---

## 今日の理解を一言でまとめる

```txt
プロパティデコレーターの target には Course.prototype が入り、
Course.prototype.constructor は Course を指す。
だから target.constructor.name は "Course" になる。
```
