# 今日の学習ログ：デコレーターで登録したバリデーションを `validate()` で実行する流れ

## 今日のテーマ

今日は、TypeScript のデコレーターを使ったバリデーションコードについて、
**デコレーターで登録したルールを、`validate(createdCourse)` でどう使うのか**を復習した。

特に、次の流れを確認した。

```ts
target.constructor.name
```

と

```ts
obj.constructor.name
```

がどちらも `"Course"` になることで、
デコレーターで登録したルールを `validate()` 側で取り出せる、というつながりを整理した。

---

## 今日理解したこと

### 1. プロパティデコレーターの `target`

インスタンスプロパティにデコレーターを付けた場合、

```ts
class Course {
  @Required
  title: string;
}
```

デコレーターの `target` は、インスタンスそのものではなく、

```ts
Course.prototype
```

を指す。

そのため、

```ts
target.constructor
```

は `Course` クラスを指す。

なので、

```ts
target.constructor.name
```

は、

```ts
"Course"
```

になる。

イメージとしてはこう。

```ts
target = Course.prototype;
target.constructor = Course;
target.constructor.name = "Course";
```

---

## 2. `validate(createdCourse)` の `obj`

フォーム送信時に、次のように `Course` インスタンスを作る。

```ts
const createdCourse = new Course(title, price);
```

そして、

```ts
validate(createdCourse)
```

と呼び出す。

`validate` 関数はこう定義されている。

```ts
function validate(obj: any) {
  // ...
}
```

つまり、`validate(createdCourse)` と呼ぶことで、
関数の中ではこうなる。

```ts
obj = createdCourse;
```

そのため、

```ts
obj.constructor.name
```

は、

```ts
createdCourse.constructor.name
```

と同じになる。

`createdCourse` は `new Course(...)` で作ったインスタンスなので、

```ts
obj.constructor.name
```

は、

```ts
"Course"
```

になる。

---

## 3. デコレーター側と validate 側が `"Course"` でつながる

デコレーター側では、

```ts
target.constructor.name
```

が `"Course"` になる。

validate 側では、

```ts
obj.constructor.name
```

が `"Course"` になる。

つまり、どちらも同じキーを使っている。

```ts
registeredValidators["Course"]
```

そのため、デコレーターで登録したルールを、
`validate(createdCourse)` の中で取り出すことができる。

---

## 4. `if (!objValidatorConfig) return true;` の意味

```ts
if (!objValidatorConfig) {
  return true;
}
```

これは、バリデーションルールが登録されていない場合の保険。

たとえば、`registeredValidators` に `"Course"` 用の設定がなければ、

```ts
registeredValidators[obj.constructor.name]
```

は `undefined` になる。

その状態で `for...in` を回そうとするとエラーになる。

だから、

```ts
if (!objValidatorConfig) {
  return true;
}
```

で、ルールがない場合は、

```txt
チェックするものがないのでOK扱い
```

として `true` を返す。

---

## 5. `let isValid = true;` の意味

```ts
let isValid = true;
```

これは、最初は「正しい」としてスタートするための変数。

そのあと、各バリデーションを確認していく。

```ts
isValid = isValid && !!obj[prop];
```

や、

```ts
isValid = isValid && obj[prop] > 0;
```

で、1つでも失敗したら `false` になる。

つまり、

```txt
最初は合格。
途中で1つでもダメなら不合格。
```

という考え方。

---

## 今日読んだコード

```ts
for (const prop in objValidatorConfig) {
  const validators = objValidatorConfig[prop];

  if (!validators) {
    continue;
  }

  for (const validator of validators) {
    switch (validator) {
      case "required":
        isValid = isValid && !!obj[prop];
        break;
      case "positive":
        isValid = isValid && obj[prop] > 0;
        break;
    }
  }
}
return isValid;
```

---

## このコードの流れ

### 1. `for...in` でプロパティ名を取り出す

```ts
for (const prop in objValidatorConfig) {
```

ここでは、`objValidatorConfig` の中にあるプロパティ名を取り出す。

たとえば、設定がこうなら、

```ts
{
  title: ["required"],
  price: ["positive"]
}
```

`prop` には順番に、

```ts
"title"
"price"
```

が入る。

---

### 2. そのプロパティに登録されたバリデーションを取り出す

```ts
const validators = objValidatorConfig[prop];
```

たとえば、

```ts
objValidatorConfig["title"]
```

なら、

```ts
["required"]
```

が入る。

```ts
objValidatorConfig["price"]
```

なら、

```ts
["positive"]
```

が入る。

---

### 3. validators がなければスキップする

```ts
if (!validators) {
  continue;
}
```

これは、`validators` が存在しない場合に、そのプロパティの処理を飛ばすための保険。

`continue` は、今の処理をスキップして、次のループへ進む。

---

### 4. `for...of` でバリデーション名を1つずつ取り出す

```ts
for (const validator of validators) {
```

`validators` が、

```ts
["required"]
```

なら、`validator` には `"required"` が入る。

`validators` が、

```ts
["positive"]
```

なら、`validator` には `"positive"` が入る。

---

### 5. `switch` でバリデーションの種類ごとに処理する

```ts
switch (validator) {
  case "required":
    isValid = isValid && !!obj[prop];
    break;
  case "positive":
    isValid = isValid && obj[prop] > 0;
    break;
}
```

`validator` が `"required"` なら、空ではないかを確認する。

```ts
!!obj[prop]
```

`validator` が `"positive"` なら、0より大きいかを確認する。

```ts
obj[prop] > 0
```

---

## フォーム送信時の流れ

```ts
const courseForm = document.querySelector("form")!;

courseForm.addEventListener("submit", (event) => {
  event.preventDefault();

  const titleEl = document.getElementById("title") as HTMLInputElement;
  const priceEl = document.getElementById("price") as HTMLInputElement;

  const title = titleEl.value;
  const price = +priceEl.value;

  const createdCourse = new Course(title, price);

  if (!validate(createdCourse)) {
    alert("正しく入力して下さい！");
    return;
  }

  console.log(createdCourse);
});
```

この流れはこう。

```txt
フォーム送信
↓
submit イベントが発火
↓
event.preventDefault() でページ再読み込みを止める
↓
title と price の入力値を取得
↓
new Course(title, price) で Course インスタンスを作る
↓
validate(createdCourse) でバリデーションする
↓
false なら alert を出して return
↓
true なら console.log(createdCourse)
```

---

## 今日の重要ポイント

今回のコードの一番大事な流れはこれ。

```txt
デコレーターでルールを登録する
↓
registeredValidators["Course"] に保存される
↓
フォーム送信時に new Course(title, price) する
↓
validate(createdCourse) を呼ぶ
↓
obj.constructor.name が "Course" になる
↓
registeredValidators["Course"] を取り出す
↓
title と price をチェックする
```

つまり、

```txt
デコレーターはその場でチェックしているのではなく、
あとで validate が使うためのルールを登録している。
```
