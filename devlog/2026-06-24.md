# 学習ログ：TypeScript デコレーターによるバリデーションの流れを読む

## 今日のテーマ

今日は、TypeScript のデコレーターを使ったバリデーションコードのうち、`validate` 関数の前半を復習した。

特に、次の2行を重点的に確認した。

```ts
for (const prop in objValidatorConfig) {
  const validators = objValidatorConfig[prop];
}
```

## 今日理解したこと

`validate(createdCourse)` が呼ばれると、まず `registeredValidators` から `Course` 用のバリデーション設定を取り出す。

イメージとしては、`objValidatorConfig` は次のような形になる。

```ts
const objValidatorConfig = {
  title: ["required"],
  price: ["positive"],
};
```

この状態で、次のコードを読む。

```ts
for (const prop in objValidatorConfig) {
  const validators = objValidatorConfig[prop];
}
```

## `for...in` の役割

```ts
for (const prop in objValidatorConfig) {
```

これは、`objValidatorConfig` のプロパティ名を1つずつ取り出す処理。

今回の場合、`prop` には順番に次の値が入る。

```ts
prop = "title";
prop = "price";
```

つまり、`for...in` はオブジェクトのキーを取り出している。

## `objValidatorConfig[prop]` の意味

```ts
const validators = objValidatorConfig[prop];
```

これは、今取り出している `prop` に対応するバリデーション配列を取得している。

たとえば、`prop` が `"title"` のとき、

```ts
const validators = objValidatorConfig["title"];
```

となる。

`objValidatorConfig["title"]` は、

```ts
["required"];
```

なので、

```ts
validators = ["required"];
```

になる。

一方、`prop` が `"price"` のときは、

```ts
const validators = objValidatorConfig["price"];
```

となる。

`objValidatorConfig["price"]` は、

```ts
["positive"];
```

なので、

```ts
validators = ["positive"];
```

になる。

## ここで気づいたこと

`validate` 関数の後半を理解するには、先に前半のデコレーター関数が何をしているのかを理解する必要があると気づいた。

特に、次のコードがまだ十分に読めていないことが分かった。

```ts
function Required(target: any, propName: string) {
  registeredValidators[target.constructor.name] = {
    ...registeredValidators[target.constructor.name],
    [propName]: [
      ...(registeredValidators[target.constructor.name]?.[propName] ?? []),
      "required",
    ],
  };
}
```

このコードは、`@Required` が付いたプロパティに対して、`"required"` というバリデーションルールを登録している。

```ts
class Course {
  @Required
  title: string;
}
```

この場合、`@Required` は `title` に付いているため、`propName` には `"title"` が入る。

イメージとしては、TypeScript が裏側で次のように呼び出している。

```ts
Required(Course.prototype, "title");
```

そのため、

```ts
target = Course.prototype;
propName = "title";
```

となる。

そして、

```ts
target.constructor.name;
```

は、

```ts
"Course";
```

になる。

つまり、最終的には次のような情報を作っている。

```ts
registeredValidators = {
  Course: {
    title: ["required"],
  },
};
```

`@PositiveNumber` も実行されると、最終的には次のような形になる。

```ts
registeredValidators = {
  Course: {
    title: ["required"],
    price: ["positive"],
  },
};
```

## 今日理解できた流れ

今日理解できた流れは次の通り。

```ts
@Required
title: string;

@PositiveNumber
price: number;
```

このデコレーターによって、まずバリデーション設定が登録される。

```ts
registeredValidators = {
  Course: {
    title: ["required"],
    price: ["positive"],
  },
};
```

そのあと、フォーム送信時に `Course` オブジェクトが作成される。

```ts
const createdCourse = new Course(title, price);
```

そして、

```ts
validate(createdCourse);
```

が呼ばれる。

`validate` の中で、`Course` 用の設定を取り出す。

```ts
const objValidatorConfig = registeredValidators[obj.constructor.name];
```

`obj.constructor.name` は `"Course"` なので、実質こうなる。

```ts
const objValidatorConfig = registeredValidators["Course"];
```

その結果、`objValidatorConfig` は次のようになる。

```ts
const objValidatorConfig = {
  title: ["required"],
  price: ["positive"],
};
```

そして、今日理解したコードにつながる。

```ts
for (const prop in objValidatorConfig) {
  const validators = objValidatorConfig[prop];
}
```

このコードによって、

```ts
prop = "title";
validators = ["required"];
```

または、

```ts
prop = "price";
validators = ["positive"];
```

という形で、チェック対象のプロパティ名と、そのプロパティに必要なバリデーションルールを取り出している。

## 今日の重要ポイント

今日一番大事だったのは、次の理解。

```ts
const validators = objValidatorConfig[prop];
```

これは、`prop` の値によって動的にプロパティを取り出している。

つまり、`prop` が `"title"` なら、

```ts
objValidatorConfig["title"];
```

となり、結果は、

```ts
["required"];
```

になる。

`prop` が `"price"` なら、

```ts
objValidatorConfig["price"];
```

となり、結果は、

```ts
["positive"];
```

になる。

## 明日やること

明日は、まず今日の復習をする。

そのあと、次のコードに進む。

```ts
if (!validators) {
  continue;
}

for (const validator of validators) {
  switch (validator) {
    case "required":
      isValid = isValid && !!obj[prop];
      break;
    case "positive":
      isValid = isValid && obj[prop] > 0;
      break;
  }
}
return isValid;
```

次に確認するポイントは以下。

```ts
if (!validators) {
  continue;
}
```

これは何を飛ばしているのか。

```ts
for (const validator of validators)
```

ここで `validators` 配列の中身をどう取り出しているのか。

```ts
switch (validator)
```

ここで `"required"` と `"positive"` によって処理を分けていること。

```ts
isValid = isValid && !!obj[prop];
```

ここで `title` が空かどうかをチェックしていること。

```ts
isValid = isValid && obj[prop] > 0;
```

ここで `price` が 0 より大きいかをチェックしていること。

## 明日の開始位置

明日はこの流れから再開する。

```ts
for (const prop in objValidatorConfig) {
  const validators = objValidatorConfig[prop];

  if (!validators) {
    continue;
  }

  for (const validator of validators) {
    switch (validator) {
      case "required":
        isValid = isValid && !!obj[prop];
        break;
      case "positive":
        isValid = isValid && obj[prop] > 0;
        break;
    }
  }
}
return isValid;
```

## 今日の感想

今日は、`validate` 関数の後半を読もうとしたことで、前半のデコレーター関数の理解がまだ足りていないことに気づけた。

特に、`objValidatorConfig[prop]` がなぜ `["required"]` や `["positive"]` になるのかを考えることで、`registeredValidators` がどのように作られているのかを復習する必要があると分かった。

まだ全体は難しいが、`prop` には `"title"` や `"price"` が入り、`validators` には `["required"]` や `["positive"]` が入る、というところまでは理解できた。
