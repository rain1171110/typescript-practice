# 学習ログ：TypeScript デコレーターのバリデーション処理を読む

## 今日のテーマ

今日は、TypeScript のデコレーターを使ったバリデーション処理のうち、`validate()` 関数の中身を中心に復習した。

特に、次の違いを重点的に確認した。

```ts
objValidatorConfig[prop];
```

```ts
obj[prop];
```

この2つは似ているが、見ているものが違う。

---

## 今日扱ったコード

```ts
function validate(obj: any) {
  let isValid = true;

  const objValidatorConfig = registeredValidators[obj.constructor.name];

  for (const prop in objValidatorConfig) {
    const validators = objValidatorConfig[prop];

    if (!validators) {
      continue;
    }

    for (const validator of validators) {
      switch (validator) {
        case "required":
          isValid = isValid && !!obj[prop];
          break;

        case "positive":
          isValid = isValid && obj[prop] > 0;
          break;
      }
    }
  }

  return isValid;
}
```

---

## 1. `objValidatorConfig` の中身

`objValidatorConfig` は、バリデーション設定を表している。

イメージとしては次のようなオブジェクト。

```ts
const objValidatorConfig = {
  title: ["required"],
  price: ["positive"],
};
```

これは、

```ts
title には required チェックをする
price には positive チェックをする
```

という意味。

---

## 2. `for...in` はキーを取り出す

```ts
for (const prop in objValidatorConfig) {
```

この `for...in` は、オブジェクトのキーを1つずつ取り出す。

```ts
const objValidatorConfig = {
  title: ["required"],
  price: ["positive"],
};
```

この場合、`prop` には順番に次の値が入る。

```ts
prop = "title";
prop = "price";
```

`["required"]` や `["positive"]` が直接入るわけではない。

---

## 3. `objValidatorConfig[prop]` の意味

```ts
const validators = objValidatorConfig[prop];
```

これは、`prop` の中身をキーとして使って、オブジェクトの値を取り出している。

たとえば、

```ts
const prop = "title";
```

なら、

```ts
objValidatorConfig[prop];
```

は、

```ts
objValidatorConfig["title"];
```

と同じになる。

その結果、

```ts
["required"];
```

が取り出される。

同じように、

```ts
const prop = "price";
```

なら、

```ts
objValidatorConfig[prop];
```

は、

```ts
objValidatorConfig["price"];
```

になり、結果は、

```ts
["positive"];
```

になる。

---

## 4. `objValidatorConfig.prop` ではダメな理由

```ts
objValidatorConfig.prop;
```

と書くと、JavaScript は `"prop"` という名前のキーを探しに行く。

しかし、今回のオブジェクトは次の形。

```ts
const objValidatorConfig = {
  title: ["required"],
  price: ["positive"],
};
```

この中に `"prop"` というキーはない。

そのため、

```ts
objValidatorConfig.prop;
```

は、

```ts
undefined;
```

になる。

整理すると、

```ts
objValidatorConfig[prop];
```

は、変数 `prop` の中身をキーとして使う。

```ts
objValidatorConfig.prop;
```

は、`"prop"` という固定のキーを探す。

---

## 5. `()` / `[]` / `.` の違い

今日混ざっていた部分として、次の違いを整理した。

```ts
objValidatorConfig("title");
```

これは関数を呼び出す書き方。

```ts
objValidatorConfig["title"];
```

これはオブジェクトのキーを指定して値を取り出す書き方。

```ts
objValidatorConfig.title;
```

これは固定のキー名で値を取り出す書き方。

つまり、今回のようにオブジェクトから値を取り出す場合は、

```ts
objValidatorConfig["title"];
```

または、

```ts
objValidatorConfig.title;
```

を使う。

変数の中身をキーとして使いたい場合は、

```ts
objValidatorConfig[prop];
```

を使う。

---

## 6. `validators` と `validator` の違い

```ts
const validators = objValidatorConfig[prop];
```

ここで `validators` には、チェックルールの配列が入る。

例：

```ts
validators = ["required"];
```

または、

```ts
validators = ["positive"];
```

次に、

```ts
for (const validator of validators) {
```

で、`validators` の中から1つずつ取り出している。

たとえば、

```ts
const validators = ["required", "positive"];

for (const validator of validators) {
  console.log(validator);
}
```

この場合、次のように表示される。

```ts
required;
positive;
```

つまり、

```ts
validators;
```

は複数のチェックルールが入った配列。

```ts
validator;
```

は、そこから取り出した1つのチェックルール。

---

## 7. `continue` と `return` の違い

```ts
if (!validators) {
  continue;
}
```

ここでは、`validators` が存在しない場合、そのプロパティの処理をスキップして次のループへ進む。

`continue` は、関数全体を終了するわけではない。

```ts
continue;
```

は、今のループをスキップして次へ進む。

一方で、

```ts
return;
```

は、関数そのものを終了する。

今回の `validate()` 関数では、途中で関数全体を終わらせたいわけではない。

そのため、

```ts
continue;
```

を使う。

---

## 8. `!!` の意味

```ts
!!obj[prop];
```

この `!!` は、値を boolean、つまり `true` / `false` に変換する書き方。

たとえば、

```ts
!!"hello"; // true
!!""; // false
!!0; // false
!!10; // true
```

今回の `required` チェックでは、

```ts
!!obj[prop];
```

で、値が空ではないかを確認している。

たとえば、

```ts
obj["title"] = "";
```

なら、

```ts
!!obj["title"];
```

は、

```ts
false;
```

になる。

---

## 9. `isValid = isValid && ...` の意味

```ts
isValid = isValid && !!obj[prop];
```

これは、

```ts
今までのチェック結果 && 今回のチェック結果;
```

という意味。

最初は、

```ts
let isValid = true;
```

として始める。

もしチェックに失敗すると、

```ts
isValid = true && false;
```

になるので、

```ts
isValid = false;
```

になる。

一度 `false` になると、その後に別のチェックが `true` でも、

```ts
isValid = false && true;
```

なので、結果はずっと `false` のまま。

つまり、

```ts
isValid = isValid && チェック結果;
```

は、

```ts
1つでもチェックに失敗したら、最終結果を false にする
```

という意味。

---

## 10. `return isValid;` の意味

```ts
return isValid;
```

これは、`validate()` 関数の結果として `isValid` の値を返している。

つまり、最終的に、

```ts
true;
```

または、

```ts
false;
```

を返す。

たとえば、

```ts
const result = validate(createdCourse);
```

と書いた場合、`validate(createdCourse)` の結果が `result` に入る。

---

## 11. `objValidatorConfig[prop]` と `obj[prop]` の違い

今日一番大事だったポイント。

```ts
objValidatorConfig[prop];
```

これは、バリデーション設定側を見ている。

例：

```ts
const objValidatorConfig = {
  title: ["required"],
  price: ["positive"],
};

const prop = "title";

objValidatorConfig[prop];
// ["required"]
```

つまり、

```ts
どのチェックをするか;
```

を見ている。

一方で、

```ts
obj[prop];
```

これは、実際の入力データ側を見ている。

たとえば、実際には次のように呼び出される。

```ts
const createdCourse = new Course("", 0);

validate(createdCourse);
```

このとき、`validate()` の中では、

```ts
function validate(obj: any) {
```

の `obj` に `createdCourse` が入る。

つまり、

```ts
obj = createdCourse;
```

のように考えられる。

そのため、

```ts
obj[prop];
```

は、実際には、

```ts
createdCourse[prop];
```

を見ている。

たとえば、

```ts
const prop = "title";
```

なら、

```ts
obj[prop];
```

は、

```ts
createdCourse["title"];
```

を見る。

もし `createdCourse.title` が空文字なら、

```ts
obj[prop];
// ""
```

になる。

---

## 今日の理解まとめ

今日の理解は次の通り。

```ts
objValidatorConfig[prop];
```

これは、登録されたバリデーション設定を見る。

```ts
obj[prop];
```

これは、実際に `validate()` に渡されたオブジェクトの値を見る。

つまり、

```ts
objValidatorConfig["title"]; // ["required"]
obj["title"]; // 実際の title の値
```

という違いがある。

---

## 今日理解できたこと

- `for...in` はオブジェクトのキーを取り出す
- `obj[key]` は、変数 `key` の中身を使って値を取り出す
- `obj.key` は、`"key"` という固定のキーを探す
- `()` は関数呼び出しに使う
- `[]` はオブジェクトのキー指定に使える
- `validators` はチェックルールの配列
- `validator` は配列から取り出した1つのチェックルール
- `continue` は今のループをスキップして次へ進む
- `return` は関数自体を終了する
- `!!` は値を `true` / `false` に変換する
- `isValid = isValid && ...` は、1つでも失敗したら `false` にする
- `return isValid;` は、最終的な `true` / `false` を返す

---

## 次回やること

次回はこの続きから実施する。

まずは、今日の最後に確認した次の違いを軽く復習する。

```ts
objValidatorConfig[prop];
```

```ts
obj[prop];
```

その後、デコレーター側に戻る。

具体的には、

```ts
function Required(target: any, propName: string) {
  registeredValidators[target.constructor.name] = {
    ...registeredValidators[target.constructor.name],
    [propName]: [
      ...(registeredValidators[target.constructor.name]?.[propName] ?? []),
      "required",
    ],
  };
}
```

```ts
function PositiveNumber(target: any, propName: string) {
  registeredValidators[target.constructor.name] = {
    ...registeredValidators[target.constructor.name],
    [propName]: [
      ...(registeredValidators[target.constructor.name]?.[propName] ?? []),
      "positive",
    ],
  };
}
```

この2つが、どのように `registeredValidators` に設定を登録しているのかを読む。

次回の開始位置は、

```ts
Required / PositiveNumber が registeredValidators にどう登録するか
```

から。
