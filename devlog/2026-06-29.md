# 学習ログ：ProjectInput のバリデーション処理を理解する

## 今日のテーマ

今日は TypeScript のプロジェクト管理アプリ課題で使われる、講義版のバリデーション処理を復習した。

前に学習した **デコレーターを使ったバリデーション** とは書き方が違っていたため、最初はかなり混乱した。

今回のバリデーションは、デコレーターでルールを登録する方式ではなく、

```ts
入力値 + チェックルール
```

をオブジェクトとして作り、それを `validate()` 関数に渡してチェックする方式だった。

---

## 今日読んだコード

```ts
interface validatable {
  value: string | number;
  required?: boolean;
  minLength?: number;
  maxLength?: number;
  min?: number;
  max?: number;
}

function validate(validatableInput: validatable) {
  let isValid = true;

  if (validatableInput.required) {
    isValid = isValid && validatableInput.value.toString().trim().length !== 0;
  }

  if (
    validatableInput.minLength != null &&
    typeof validatableInput.value === "string"
  ) {
    isValid =
      isValid && validatableInput.value.length >= validatableInput.minLength;
  }

  if (
    validatableInput.maxLength != null &&
    typeof validatableInput.value === "string"
  ) {
    isValid =
      isValid && validatableInput.value.length <= validatableInput.maxLength;
  }

  if (
    validatableInput.min != null &&
    typeof validatableInput.value === "number"
  ) {
    isValid = isValid && validatableInput.value >= validatableInput.min;
  }

  if (
    validatableInput.max != null &&
    typeof validatableInput.value === "number"
  ) {
    isValid = isValid && validatableInput.value <= validatableInput.max;
  }

  return isValid;
}
```

---

## `interface validatable` の役割

```ts
interface validatable {
  value: string | number;
  required?: boolean;
  minLength?: number;
  maxLength?: number;
  min?: number;
  max?: number;
}
```

この `interface` は、バリデーション用オブジェクトの形を決めている。

つまり、

```ts
validate()
```

に渡すオブジェクトは、こういう形にしてね、という設計図。

---

## `value` とは何か

```ts
value: string | number;
```

`value` は、実際にチェックしたい入力値。

たとえばタイトルなら文字列。

```ts
{
  value: "買い物アプリ",
  required: true
}
```

人数なら数値。

```ts
{
  value: 3,
  required: true,
  min: 1,
  max: 5
}
```

`value` は文字列の場合も数値の場合もあるので、

```ts
string | number
```

になっている。

---

## `?` が付いている理由

```ts
required?: boolean;
minLength?: number;
maxLength?: number;
min?: number;
max?: number;
```

`?` は、あってもいいし、なくてもいいという意味。

すべての入力欄に、すべてのルールを使うわけではない。

たとえば、タイトルには `required` だけでいい場合がある。

```ts
const titleValidatable: validatable = {
  value: enteredTitle,
  required: true,
};
```

説明文には `required` と `minLength` を使う。

```ts
const descriptionValidatable: validatable = {
  value: enteredDescription,
  required: true,
  minLength: 5,
};
```

人数には `min` と `max` を使う。

```ts
const peopleValidatable: validatable = {
  value: enteredPeople,
  required: true,
  min: 1,
  max: 5,
};
```

だから `required` / `minLength` / `maxLength` / `min` / `max` は optional になっている。

---

## `validate()` 関数の目的

```ts
function validate(validatableInput: validatable) {
  let isValid = true;

  // チェック処理

  return isValid;
}
```

`validate()` は、渡された入力値がルールを満たしているか確認して、最後に `true` または `false` を返す関数。

最初に、

```ts
let isValid = true;
```

としている。

これは、最初は「問題なし」として始めるという意味。

そこからチェックしていき、1つでも条件に合わなければ `false` になる。

---

## `required` のチェック

```ts
if (validatableInput.required) {
  isValid = isValid && validatableInput.value.toString().trim().length !== 0;
}
```

これは、

```ts
required: true
```

が指定されているときだけ実行される。

中身は、入力値が空ではないかをチェックしている。

```ts
validatableInput.value.toString().trim().length !== 0
```

分解すると、

```ts
validatableInput.value
```

入力値。

```ts
.toString()
```

文字列に変換。

```ts
.trim()
```

前後の空白を削除。

```ts
.length !== 0
```

文字数が 0 ではないか確認。

つまり、空文字だけでなく、

```ts
"   "
```

のような空白だけの入力も無効にできる。

---

## `isValid = isValid && ...` の意味

```ts
isValid = isValid && 条件;
```

これは、

```ts
1つでも失敗したら、最後まで false のままにする
```

ための書き方。

たとえば、最初のチェックで失敗して、

```ts
isValid = false;
```

になったとする。

そのあと別の条件が `true` でも、

```ts
false && true
```

は `false` になる。

つまり、最終的に、

```ts
全部OKなら true
1つでもダメなら false
```

にできる。

---

## `minLength` のチェック

```ts
if (
  validatableInput.minLength != null &&
  typeof validatableInput.value === "string"
) {
  isValid =
    isValid && validatableInput.value.length >= validatableInput.minLength;
}
```

これは、文字列の最小文字数をチェックしている。

たとえば、

```ts
const descriptionValidatable: validatable = {
  value: "abc",
  required: true,
  minLength: 5,
};
```

この場合、

```ts
"abc".length >= 5
```

をチェックする。

`"abc"` は 3文字なので、

```ts
3 >= 5
```

は `false`。

そのため、バリデーションは失敗する。

---

## `minLength != null` の意味

```ts
validatableInput.minLength != null
```

これは、

```ts
minLength が null でも undefined でもない
```

という意味。

つまり、

```ts
minLength のルールが指定されているならチェックする
```

ということ。

`minLength` が指定されていない入力欄では、このチェックは実行しない。

---

## `typeof validatableInput.value === "string"` の意味

```ts
typeof validatableInput.value === "string"
```

これは、`value` が文字列かどうかを確認している。

なぜ必要かというと、`value` はこのように定義されているから。

```ts
value: string | number;
```

つまり、`value` には文字列も数値も入る可能性がある。

でも `.length` は文字列には使えるが、数値には使えない。

```ts
"hello".length; // OK
```

```ts
5.length; // NG
```

だから、文字数チェックをするときは、先に `typeof` で文字列かどうか確認している。

これは型ガードの一種。

---

## `maxLength` のチェック

```ts
if (
  validatableInput.maxLength != null &&
  typeof validatableInput.value === "string"
) {
  isValid =
    isValid && validatableInput.value.length <= validatableInput.maxLength;
}
```

これは、文字列の最大文字数をチェックしている。

`maxLength` が指定されていて、かつ `value` が文字列のときだけ実行される。

---

## `min` のチェック

```ts
if (
  validatableInput.min != null &&
  typeof validatableInput.value === "number"
) {
  isValid = isValid && validatableInput.value >= validatableInput.min;
}
```

これは、数値の最小値をチェックしている。

たとえば、

```ts
const peopleValidatable: validatable = {
  value: 0,
  required: true,
  min: 1,
};
```

この場合、

```ts
0 >= 1
```

をチェックする。

これは `false` なので、バリデーションは失敗する。

---

## `max` のチェック

```ts
if (
  validatableInput.max != null &&
  typeof validatableInput.value === "number"
) {
  isValid = isValid && validatableInput.value <= validatableInput.max;
}
```

これは、数値の最大値をチェックしている。

たとえば、

```ts
const peopleValidatable: validatable = {
  value: 10,
  required: true,
  max: 5,
};
```

この場合、

```ts
10 <= 5
```

をチェックする。

これは `false` なので、バリデーションは失敗する。

## 実際の使い方のイメージ

フォームから入力値を取得する。

```ts
const enteredTitle = this.titleInputElement.value;
const enteredDescription = this.descriptionInputElement.value;
const enteredPeople = +this.peopleInputElement.value;
```

`enteredPeople` には `+` が付いている。

```ts
const enteredPeople = +this.peopleInputElement.value;
```

これは、文字列を数値に変換するため。

たとえば input の値は `"3"` のような文字列なので、

```ts
+"3"
```

とすると、

```ts
3
```

という数値になる。

## チェック用オブジェクトを作る

```ts
const titleValidatable: validatable = {
  value: enteredTitle,
  required: true,
};

const descriptionValidatable: validatable = {
  value: enteredDescription,
  required: true,
  minLength: 5,
};

const peopleValidatable: validatable = {
  value: enteredPeople,
  required: true,
  min: 1,
  max: 5,
};
```

これで、それぞれの入力値に対するルールを作れる。

タイトルは必須。

```ts
const titleValidatable: validatable = {
  value: enteredTitle,
  required: true,
};
```

説明文は必須で、5文字以上。

```ts
const descriptionValidatable: validatable = {
  value: enteredDescription,
  required: true,
  minLength: 5,
};
```

人数は必須で、1以上5以下。

```ts
const peopleValidatable: validatable = {
  value: enteredPeople,
  required: true,
  min: 1,
  max: 5,
};
```

## `validate()` に渡してチェックする

```ts
if (
  !validate(titleValidatable) ||
  !validate(descriptionValidatable) ||
  !validate(peopleValidatable)
) {
  alert("Invalid input, please try again!");
  return;
}
```

これは、

```ts
タイトルがダメ
または
説明文がダメ
または
人数がダメ
```

なら、アラートを出して処理を止めるという意味。

`validate()` は OK なら `true` を返す。

でも、ここでは `!validate(...)` と書いている。

```ts
!validate(titleValidatable)
```

なので、バリデーション失敗時に `true` になる。

つまり、

```ts
どれか1つでも失敗したら alert を出す
```

という処理になる。

## デコレーター版バリデーションとの違い

前に学習したデコレーター版では、クラスのプロパティにルールを書いた。

```ts
class Course {
  @Required
  title: string;

  @PositiveNumber
  price: number;
}
```

この場合は、デコレーターによって裏側の `registeredValidators` にルールを登録していた。

つまり、

```ts
クラスのプロパティにルールを付ける方式
```

だった。

今回の ProjectInput のバリデーションは違う。

```ts
const titleValidatable: validatable = {
  value: enteredTitle,
  required: true,
};
```

このように、

```ts
入力値とルールをオブジェクトにして validate に渡す方式
```

だった。

## 今日の理解

今日の時点で理解したこと。

* `interface validatable` は、バリデーション用オブジェクトの型
* `value` は、実際にチェックしたい入力値
* `required?` や `minLength?` は、必要なときだけ指定できるルール
* `validate()` は、入力値がルールを満たしているか確認する関数
* `isValid = isValid && 条件` は、1つでも失敗したら false にするための書き方
* `minLength != null` は、ルールが指定されているか確認している
* `typeof validatableInput.value === "string"` は、文字列だけに `.length` を使うための型ガード
* `typeof validatableInput.value === "number"` は、数値だけに `min` / `max` を使うための型ガード
* 今回のバリデーションは、デコレーター版とは違い、入力値とルールをその場でオブジェクトにして渡す方式

---

## 今日のまとめ

今回のバリデーション処理は、最初はデコレーター版と全然違って見えて混乱した。

でも、やっていることはシンプルで、

```ts
入力値を用意する
チェックルールをオブジェクトにする
validate() に渡す
true / false を返す
```

という流れだった。

特に重要なのは、`validatable` オブジェクトが、

```ts
value
+
required / minLength / maxLength / min / max
```

をセットで持っていること。

つまり、`validate()` は「値だけ」を見ているのではなく、

```ts
どの値を、どのルールでチェックするか
```

を受け取って判定している。
