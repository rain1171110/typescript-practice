## 今日学んだこと

今日は、プロジェクト管理アプリで **実行中プロジェクトを完了プロジェクトへ移動する処理** について学習した。

まず、完了プロジェクトに新しく追加するのではなく、既に存在しているプロジェクトの `status` を変更することで表示先が変わる、という考え方を確認した。

```ts
project.status = newStatus;
```

この処理によって、ProjectState の中にある本体データの `status` が変更される。

例えば、実行中だったプロジェクトは次のような状態から、

```ts
{
  id: "abc",
  title: "買い物アプリ",
  status: ProjectStatus.Active
}
```

次のような状態に変わる。

```ts
{
  id: "abc",
  title: "買い物アプリ",
  status: ProjectStatus.Finished
}
```

つまり、`project.status = newStatus;` は、プロジェクトの状態を変更する本体の処理である。

---

## `moveProject()` の役割

`moveProject()` は、指定された `projectId` を使って対象のプロジェクトを探し、そのプロジェクトの `status` を変更するメソッドである。

```ts
moveProject(projectId: string, newStatus: ProjectStatus) {
  const project = this.projects.find((prj) => prj.id === projectId);

  if (project && project.status !== newStatus) {
    project.status = newStatus;
    this.updateListeners();
  }
}
```

このコードでは、まず `this.projects.find()` を使って、ProjectState が持っている全プロジェクトの中から、指定された `id` と一致するプロジェクトを探している。

```ts
const project = this.projects.find((prj) => prj.id === projectId);
```

その後、プロジェクトが見つかり、現在の `status` と新しい `status` が違う場合だけ、状態を変更する。

```ts
if (project && project.status !== newStatus) {
  project.status = newStatus;
  this.updateListeners();
}
```

ここで重要なのは、`status` を変更しただけでは画面は自動で変わらないという点である。

---

## なぜ `updateListeners()` が必要なのか

`project.status = newStatus;` によって、ProjectState の中の本体データは変更される。

しかし、画面に表示している ProjectList は、ProjectState の `projects` を直接見ているわけではない。

ProjectList は、自分自身の `assignedProjects` をもとに画面を表示している。

```ts
assignedProjects: Project[] = [];
```

そして、画面表示ではこの `assignedProjects` を使っている。

```ts
for (const prjItem of this.assignedProjects) {
  const listItem = document.createElement("li");
  listItem.textContent = prjItem.title;
  listEl.appendChild(listItem);
}
```

つまり、構造としては次のようになっている。

```txt
ProjectState
  └─ projects ← 本体データ

ProjectList
  └─ assignedProjects ← 表示用データ
```

`moveProject()` で変更しているのは、ProjectState の `projects` である。

しかし、画面表示に使っているのは、ProjectList の `assignedProjects` である。

そのため、ProjectState のデータを変更したあとに、ProjectList に対して「データが変わったので表示を更新してほしい」と知らせる必要がある。

その役割を持つのが、次の処理である。

```ts
this.updateListeners();
```

---

## `updateListeners()` の中身

`updateListeners()` は、登録されている listener 関数をすべて実行し、最新の `projects` 配列を渡す処理である。

```ts
private updateListeners() {
  for (const listenerFn of this.listeners) {
    listenerFn(this.projects.slice());
  }
}
```

ここで重要なのは、次の部分である。

```ts
listenerFn(this.projects.slice());
```

これは、ProjectState が持っている最新の `projects` 配列のコピーを listener 関数に渡している。

この値は、ProjectList 側で登録している次の関数の `projects` に入る。

```ts
projectState.addListener((projects: Project[]) => {
  const relevantProjects = projects.filter((prj) => {
    if (this.type === "active") {
      return prj.status === ProjectStatus.Active;
    }
    return prj.status === ProjectStatus.Finished;
  });

  this.assignedProjects = relevantProjects;
  this.renderProjects();
});
```

対応関係は次のようになる。

```ts
listenerFn(this.projects.slice());
//         ↓
(projects: Project[]) => {
```

つまり、`this.projects.slice()` で渡された最新のプロジェクト一覧が、ProjectList 側の `projects` に入る。

---

## ProjectList 側で起きること

`updateListeners()` によって listener が実行されると、ProjectList 側では、最新の `projects` をもとに `filter()` が再実行される。

```ts
const relevantProjects = projects.filter((prj) => {
  if (this.type === "active") {
    return prj.status === ProjectStatus.Active;
  }
  return prj.status === ProjectStatus.Finished;
});
```

実行中リストの場合は、`ProjectStatus.Active` のプロジェクトだけを取り出す。

```ts
return prj.status === ProjectStatus.Active;
```

完了リストの場合は、`ProjectStatus.Finished` のプロジェクトだけを取り出す。

```ts
return prj.status === ProjectStatus.Finished;
```

その結果を、ProjectList の表示用配列である `assignedProjects` に入れる。

```ts
this.assignedProjects = relevantProjects;
```

最後に、画面を再描画する。

```ts
this.renderProjects();
```

---

## `renderProjects()` の役割

`renderProjects()` は、現在の `assignedProjects` をもとに画面を作り直す処理である。

```ts
private renderProjects() {
  const listEl = document.getElementById(
    `${this.type}-projects-list`,
  )! as HTMLUListElement;

  listEl.innerHTML = "";

  for (const prjItem of this.assignedProjects) {
    const listItem = document.createElement("li");
    listItem.textContent = prjItem.title;
    listEl.appendChild(listItem);
  }
}
```

最初に、現在表示されている `<li>` を一度すべて消す。

```ts
listEl.innerHTML = "";
```

その後、最新の `assignedProjects` を使って、もう一度 `<li>` を作成する。

```ts
for (const prjItem of this.assignedProjects) {
  const listItem = document.createElement("li");
  listItem.textContent = prjItem.title;
  listEl.appendChild(listItem);
}
```

これによって、古い表示を消して、最新の状態で画面を作り直すことができる。

## 今日理解した流れ

```txt
project.status = newStatus;
↓
ProjectState の本体データが変わる
↓
this.updateListeners();
↓
listenerFn(this.projects.slice()) が実行される
↓
ProjectList 側の addListener の中の関数が動く
↓
projects に最新の projects 配列が入る
↓
filter で active / finished に分け直す
↓
this.assignedProjects = relevantProjects;
↓
this.renderProjects();
↓
画面の li を全部消して、最新状態で作り直す
```

---

## 今日の理解ポイント

今日一番大事だったのは、`moveProject()` はプロジェクトを別の配列へ直接移動しているわけではない、という点である。

実際には、プロジェクトの `status` を変更している。

```ts
project.status = newStatus;
```

その後、`updateListeners()` によって ProjectList に最新のデータを渡し直す。

```ts
this.updateListeners();
```

ProjectList は受け取った最新データを `filter()` で再分類し、`assignedProjects` を更新し、`renderProjects()` で画面を作り直す。

---

## たとえ

ProjectState は「倉庫」のようなもの。

```txt
ProjectState の projects
= 本体データが入っている倉庫
```

ProjectList は「掲示板」のようなもの。

```txt
ProjectList の assignedProjects
= 掲示板に貼るための表示用データ
```

倉庫の中身を変えただけでは、掲示板は勝手に貼り替わらない。

だから、`updateListeners()` を使って、

```txt
倉庫の中身が変わったので、掲示板を貼り替えてください
```

と知らせている。
