## テーマ：Validation処理と入力チェックの共通化

今日は、TypeScript のプロジェクト管理アプリの模範解答講義として、`ProjectInput` / `ProjectList` に加えて、入力値をチェックする `Validation` の仕組みを学習した。

## 今日学んだこと

今回の中心は、入力チェックを `gatherUserInput()` の中に直接書くのではなく、`Validatable` interface と `validate()` 関数に分けて整理することだった。

以前は、入力値が空かどうかを直接 if 文で確認していた。

```ts
if (
  enteredTitle.trim().length === 0 ||
  enteredDescription.trim().length === 0 ||
  enteredManday.trim().length === 0
) {
  alert("入力値が正しくありません。再度お試しください。");
  return;
}
```

今回からは、入力値ごとにチェック設定オブジェクトを作り、それを `validate()` に渡して判定する形になった。

```ts
const titleValidatable: Validatable = {
  value: enteredTitle,
  required: true,
  minLength: 5,
};

const descriptionValidatable: Validatable = {
  value: enteredDescription,
  required: true,
};

const mandayValidatable: Validatable = {
  value: +enteredManday,
  required: true,
  min: 1,
  max: 1000,
};
```

---

## Validatable interface の役割

`Validatable` は、入力チェックのルールを表すための型。

```ts
interface Validatable {
  value: string | number;
  required?: boolean;
  minLength?: number;
  maxLength?: number;
  min?: number;
  max?: number;
}
```

`value` はチェック対象の値なので必須。

一方で、`required` / `minLength` / `maxLength` / `min` / `max` は、入力欄によって必要なチェックが違うため、`?` を付けて任意プロパティにしている。

例えば、タイトルは文字列なので `minLength` を使う。

```ts
const titleValidatable: Validatable = {
  value: enteredTitle,
  required: true,
  minLength: 5,
};
```

工数は数値なので `min` / `max` を使う。

```ts
const mandayValidatable: Validatable = {
  value: +enteredManday,
  required: true,
  min: 1,
  max: 1000,
};
```

---

## validate関数の役割

`validate()` は、`Validatable` 型のオブジェクトを受け取り、入力値が正しいかどうかを `true` / `false` で返す関数。

```ts
function validate(validatableInput: Validatable) {
  let isValid = true;

  if (validatableInput.required) {
    isValid = isValid && validatableInput.value.toString().trim().length !== 0;
  }

  if (
    validatableInput.minLength != null &&
    typeof validatableInput.value === "string"
  ) {
    isValid =
      isValid && validatableInput.value.length >= validatableInput.minLength;
  }

  if (
    validatableInput.maxLength != null &&
    typeof validatableInput.value === "string"
  ) {
    isValid =
      isValid && validatableInput.value.length <= validatableInput.maxLength;
  }

  if (
    validatableInput.min != null &&
    typeof validatableInput.value === "number"
  ) {
    isValid = isValid && validatableInput.value >= validatableInput.min;
  }

  if (
    validatableInput.max != null &&
    typeof validatableInput.value === "number"
  ) {
    isValid = isValid && validatableInput.value <= validatableInput.max;
  }

  return isValid;
}
```

---

## `isValid = isValid && 条件` の考え方

今回の重要ポイントはここ。

```ts
isValid = isValid && 条件;
```

これは、

```txt
今までOKで、今回の条件もOKなら true
どこかで一度でも失敗したら false のまま
```

という意味。

例えば、タイトルが `"abc"` の場合、空ではないので `required` は成功する。

しかし、`minLength: 5` に対して3文字しかないので、文字数チェックで失敗する。

```ts
true && false
```

になるため、最終的に `isValid` は `false` になる。

---

## `!= null` の意味

`validate()` の中では、次のような条件が出てきた。

```ts
validatableInput.minLength != null
```

これは、`minLength` が `null` でも `undefined` でもないことを確認している。

つまり、

```txt
minLength が設定されているならチェックする
```

という意味。

今回のように「そのチェック項目が設定されているか」を確認したい場面で使われている。

---

## `typeof` を使う理由

`value` は `string | number` なので、文字列の場合も数値の場合もある。

そのため、文字数チェックをするときは、先に文字列かどうかを確認する必要がある。

```ts
typeof validatableInput.value === "string"
```

これがないと、数値に対して `.length` を使おうとしてしまう可能性がある。

数値の範囲チェックでは、逆に `number` かどうかを確認している。

```ts
typeof validatableInput.value === "number"
```

## gatherUserInput の流れ

`gatherUserInput()` では、入力値を取得したあと、それぞれの入力値に対してチェック設定オブジェクトを作る。

```ts
private gatherUserInput(): [string, string, number] | void {
  const enteredTitle = this.titleInputElement.value;
  const enteredDescription = this.descriptionInputElement.value;
  const enteredManday = this.mandayInputElement.value;

  const titleValidatable: Validatable = {
    value: enteredTitle,
    required: true,
    minLength: 5,
  };

  const descriptionValidatable: Validatable = {
    value: enteredDescription,
    required: true,
  };

  const mandayValidatable: Validatable = {
    value: +enteredManday,
    required: true,
    min: 1,
    max: 1000,
  };

  if (
    !validate(titleValidatable) ||
    !validate(descriptionValidatable) ||
    !validate(mandayValidatable)
  ) {
    alert("入力値が正しくありません。再度お試しください。");
    return;
  } else {
    return [enteredTitle, enteredDescription, +enteredManday];
  }
}
```

`validate()` は、正しければ `true`、不正なら `false` を返す。

そのため、

```ts
!validate(titleValidatable)
```

は、

```txt
タイトルが不正なら true
```

という意味になる。

つまり、この if 文は、

```txt
タイトルが不正
または
説明文が不正
または
工数が不正

なら alert を出して return
```

という処理になっている。

## 今日修正・確認したポイント

`ProjectList` の `listId` は、スペースを入れずに書く。

```ts
const listId = `${this.type}-projects-list`;
```

これにより、`active` の場合は、

```txt
active-projects-list
```

```txt
finished-projects-list
```

になる。

また、HTML 側で `description` が `<textarea>` の場合、TypeScript の型は `HTMLInputElement` よりも `HTMLTextAreaElement` の方が正確。

```ts
descriptionInputElement: HTMLTextAreaElement;
```

```ts
this.descriptionInputElement = this.element.querySelector(
  "#description",
) as HTMLTextAreaElement;
```

## 今日の理解まとめ

今日の内容は、入力チェックの処理を整理するための内容だった。

重要な理解は以下。

```txt
Validatable は「入力チェック設定用の型」

validate() は「チェック設定を受け取って true / false を返す関数」

gatherUserInput() は、
入力値を取得する
↓
チェック設定オブジェクトを作る
↓
validate() に渡す
↓
どれか1つでも不正なら alert
↓
全部OKならタプルで返す
```

今までは if 文に直接条件を書いていたが、今回からは入力チェックのルールをオブジェクトとして整理できるようになった。

これにより、コードは少し長くなるが、どの入力欄にどんなチェックをするのかが分かりやすくなる。
