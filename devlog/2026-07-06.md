# 学習ログ：ProjectState / static / Singleton の整理

## 今日のテーマ

今日は TypeScript の ProjectState クラスについて学習した。  
特に、`static`、`private constructor()`、`getInstance()`、`this.instance`、`this.projects` の違いを整理した。

---

## 学習したコード

```ts
// Project State Management
class ProjectState {
  private projects: any[] = [];
  private static instance: ProjectState;

  private constructor() {}

  static getInstance() {
    if (this.instance) {
      return this.instance;
    }

    this.instance = new ProjectState();
    return this.instance;
  }

  addProject(title: string, description: string, manday: number) {
    const newProject = {
      id: Math.random().toString(),
      title: title,
      description: description,
      manday: manday,
    };

    this.projects.push(newProject);
  }
}

const projectState = ProjectState.getInstance();
```

---

## `private projects` の役割

```ts
private projects: any[] = [];
```

これは、ProjectState インスタンスが持つプロジェクト一覧データ。

`private` にすることで、クラスの外から直接 `projects` を触れないようにしている。

```ts
projectState.projects.push(...); // エラー
```

つまり、`private projects` は、

> projects 配列の中身を外から直接いじらせないため

に使う。

---

## `private constructor()` の役割

```ts
private constructor() {}
```

これは、外から `new ProjectState()` できないようにするため。

もし constructor が private でなければ、外から何個でも ProjectState を作れてしまう。

```ts
const state1 = new ProjectState();
const state2 = new ProjectState();
```

すると、それぞれ別々の `projects` 配列を持ってしまう。

```ts
state1.projects = [];
state2.projects = [];
```

これでは、アプリ全体のデータ置き場が複数に分かれてしまう。

そのため、ProjectState を1個だけにしたい場合は、`private constructor()` にする。

---

## `private projects` と `private constructor()` の違い

```ts
private projects: any[] = [];
```

これは、

> 中のデータを守る

ため。

```ts
private constructor() {}
```

これは、

> ProjectState 自体を外から勝手に作らせない

ため。

つまり、守っている対象が違う。

---

## `static` の意味

`static` は、

> インスタンスを作らなくても、クラスから直接使えるもの

という意味。

今回のコードでは、これが static。

```ts
private static instance: ProjectState;

static getInstance() {
  // ...
}
```

なので、こう呼べる。

```ts
ProjectState.getInstance();
```

これは、

```ts
const projectState = new ProjectState();
projectState.getInstance();
```

ではなく、

```ts
ProjectState.getInstance();
```

のように、クラスから直接呼んでいる。

---

## なぜ `getInstance()` は static にするのか

`getInstance()` は、

> ProjectState の唯一のインスタンスを取得する入口

として使う。

まだインスタンスがない状態でも呼びたいので、static にする必要がある。

もし static ではなかったら、こう呼ぶ必要がある。

```ts
const state = new ProjectState();
state.getInstance();
```

しかし、これでは `getInstance()` を呼ぶために先に `new ProjectState()` する必要がある。

Singleton にしたいのに、先に `new` できてしまうのはおかしい。

だから、`getInstance()` は static にして、

```ts
ProjectState.getInstance();
```

と呼べるようにする。

---

## `ProjectState.getInstance()` と `new ProjectState()` の違い

```ts
new ProjectState();
```

これは、呼ぶたびに新しいインスタンスを作る。

```ts
const state1 = new ProjectState();
const state2 = new ProjectState();

console.log(state1 === state2); // false
```

一方で、

```ts
ProjectState.getInstance();
```

これは、まだインスタンスがなければ作る。  
すでにあれば、前に作った同じインスタンスを返す。

```ts
const state1 = ProjectState.getInstance();
const state2 = ProjectState.getInstance();

console.log(state1 === state2); // true
```

つまり、`ProjectState.getInstance()` は `new` の別名ではない。

正しくは、

> 必要なら1回だけ `new ProjectState()` するメソッド

である。

---

## `this.instance` の `this`

static メソッドの中では、`this` はインスタンスではなく、クラス自身を指す。

```ts
static getInstance() {
  if (this.instance) {
    return this.instance;
  }

  this.instance = new ProjectState();
  return this.instance;
}
```

この中の、

```ts
this.instance
```

は、ほぼ次の意味で考えてよい。

```ts
ProjectState.instance
```

つまり、

```ts
this.instance
```

は、

> ProjectState クラス自身が持っている static な instance

を指している。

---

## `this.projects` の `this`

一方で、普通のメソッドの中では、`this` はインスタンスを指す。

```ts
addProject(title: string, description: string, manday: number) {
  const newProject = {
    id: Math.random().toString(),
    title: title,
    description: description,
    manday: manday,
  };

  this.projects.push(newProject);
}
```

この中の、

```ts
this.projects
```

は、次のように考えてよい。

```ts
projectState.projects
```

つまり、

```ts
this.projects
```

は、

> projectState インスタンスが持っている projects

を指している。

---

## 今日整理できた重要ポイント

```ts
this.instance
```

は、static メソッドの中では、

```ts
ProjectState.instance
```

と考える。

```ts
this.projects
```

は、普通のメソッドの中では、

```ts
projectState.projects
```

と考える。

整理すると、

```txt
this.instance は ProjectState.instance
this.projects は projectState.projects
```

---

## 呼び出し方の違い

static メソッドは、クラスから呼ぶ。

```ts
ProjectState.getInstance();
```

普通のメソッドは、インスタンスから呼ぶ。

```ts
projectState.addProject("勉強", "TypeScript", 3);
```

つまり、

```ts
ProjectState.getInstance();
```

は、

> ProjectState の唯一のインスタンスを取得する

ための呼び出し。

```ts
projectState.addProject();
```

は、

> 取得したインスタンスを使って、プロジェクトを追加する

ための呼び出し。

---

## class の中と外の違い

これは正しい。

```ts
class ProjectState {
  private static instance: ProjectState;

  private constructor() {}

  static getInstance() {
    if (this.instance) {
      return this.instance;
    }

    this.instance = new ProjectState();
    return this.instance;
  }
}

const projectState = ProjectState.getInstance();
```

`const projectState = ProjectState.getInstance();` は class の外に書く。

これは、ProjectState クラスを定義したあとに、実際に使い始めるためのコード。

---

## class の中に直接実行文は書けない

これはできない。

```ts
class ProjectState {
  ProjectState.getInstance(); // エラー
}
```

理由は、class の中に普通の実行文を直接書けないから。

class の中に書けるのは、基本的に以下のようなもの。

```ts
class ProjectState {
  private projects: any[] = [];

  constructor() {}

  static getInstance() {}

  addProject() {}
}
```

ただし、メソッドの中なら実行文を書ける。

```ts
class ProjectInput {
  submitHandler() {
    const projectState = ProjectState.getInstance();
  }
}
```

これはOK。

---

## 今日の理解

今日の学習で、以下のように整理できた。

```txt
private projects
→ projects 配列を外から直接触らせないため

private constructor
→ 外から new ProjectState() させないため

static getInstance
→ インスタンスがなくても ProjectState.getInstance() で呼べるようにするため

ProjectState.getInstance()
→ 唯一の ProjectState インスタンスを取得する入口

new ProjectState()
→ 毎回新しいインスタンスを作る

this.instance
→ static メソッド内では ProjectState.instance

this.projects
→ 普通のメソッド内では projectState.projects
```
